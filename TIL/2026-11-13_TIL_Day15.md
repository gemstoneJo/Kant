## 1. 오늘의 학습 내용과 전체 흐름

오늘은 어제 배운 Docker를 활용해 **PostgreSQL 데이터베이스를 만들고 SQL로 데이터를 저장·조회하는 과정**을 실습했다.

오전에는 Docker CLI와 SQL을 중심으로 실습했고, 오후에는 Docker Compose와 DBCode를 활용해 데이터베이스를 관리했다.

### 전체 학습 흐름

```text
Docker로 PostgreSQL 실행
        ↓
kant_shop.sql 파일 작성
        ↓
kant_shop 데이터베이스 생성
        ↓
product 테이블 생성
        ↓
상품 데이터 5개 입력
        ↓
SQL로 상품 조회
        ↓
Docker Volume 생성 및 연결
        ↓
컨테이너 삭제·재생성 후 데이터 확인
        ↓
compose.yaml 작성
        ↓
Docker Compose로 PostgreSQL 실행
        ↓
VS Code DBCode 설치
        ↓
localhost:5433 접속 및 데이터 확인
```

### 오늘의 핵심 개념

| 개념 | 역할 |
|---|---|
| PostgreSQL | 데이터베이스 관리 프로그램(DBMS) |
| SQL | 데이터베이스에 명령을 내리는 언어 |
| Docker CLI | 터미널 명령어로 컨테이너 관리 |
| Docker Volume | 데이터를 컨테이너와 별도로 저장 |
| Docker Compose | YAML 파일로 컨테이너 실행 설정 관리 |
| DBCode | VS Code에서 데이터베이스를 확인하는 확장 프로그램 |

## 2. Docker CLI로 PostgreSQL 실행

### PostgreSQL 컨테이너 생성

```bash
docker run -d --name my-pg -e POSTGRES_PASSWORD=admin1234 -p 5432:5432 postgres:18
```

긴 명령어는 다음과 같이 여러 줄로 작성할 수 있다.

```bash
docker run -d --name my-pg \
-e POSTGRES_PASSWORD=admin1234 \
-p 5432:5432 postgres:18
```

| 명령어 | 기능 |
|---|---|
| `docker run` | 새 컨테이너 생성 및 실행 |
| `-d` | 백그라운드 실행 |
| `--name my-pg` | 컨테이너 이름 지정 |
| `-e` | 환경변수 전달 |
| `POSTGRES_PASSWORD=admin1234` | PostgreSQL 관리자 비밀번호 설정 |
| `-p 5432:5432` | 호스트와 컨테이너 포트 연결 |
| `postgres:18` | PostgreSQL 18 이미지 사용 |

### 컨테이너 목록 조회

```bash
docker ps
```

현재 실행 중인 컨테이너를 확인한다.

```bash
docker ps -a
```

종료된 컨테이너까지 모두 확인한다.

## 3. SQL 파일 작성하기

파일 이름: `kant_shop.sql`

```bash
touch kant_shop.sql
```

SQL 파일에 데이터베이스 생성, 테이블 생성, 상품 데이터 입력 명령어를 작성했다.

### 실제 작성한 SQL 코드

```sql
-- 1. 데이터베이스 생성
DROP DATABASE IF EXISTS kant_shop;

CREATE DATABASE kant_shop;

-- 2. 새로 만든 데이터베이스 접속
\c kant_shop

-- 3. 상품 테이블 생성
CREATE TABLE product
(
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    price INT NOT NULL,
    stock INT NOT NULL
);

-- 4. 상품 초기 데이터 입력
INSERT INTO product (name, price, stock) VALUES
('무선이어폰', 35000, 100),
('게이밍 마우스', 28000, 85),
('27인치 모니터', 259000, 15),
('USB-C 허브', 19900, 200),
('노트북 거치대', 24000, 7);
```

### SQL 명령어의 역할

| 명령어 | 설명 |
|---|---|
| `DROP DATABASE` | 데이터베이스 삭제 |
| `IF EXISTS` | 대상이 존재하는 경우에만 처리 |
| `CREATE DATABASE` | 데이터베이스 생성 |
| `\c kant_shop` | psql에서 해당 데이터베이스로 접속 전환 |
| `CREATE TABLE` | 테이블 구조 생성 |
| `INSERT INTO` | 테이블에 데이터 입력 |
| `VALUES` | 입력할 값 지정 |
| `SELECT` | 데이터 조회 |

### 데이터 타입과 제약 조건

| 문법 | 의미 |
|---|---|
| `SERIAL` | 자동 증가 번호 생성 |
| `PRIMARY KEY` | 중복되지 않는 기본키 |
| `VARCHAR(100)` | 최대 100자의 문자열 |
| `INT` | 정수 |
| `NOT NULL` | NULL 값 저장 불가 |

**주의:** `DROP DATABASE`는 기존 데이터베이스를 삭제하므로 실제 중요한 데이터를 다룰 때는 주의해야 한다.

## 4. SQL 파일 실행 방법 두 가지

### 첫 번째 방법 — 컨테이너로 파일 복사 후 실행

```bash
docker cp kant_shop.sql my-pg:/tmp/kant_shop.sql
```

로컬 SQL 파일을 컨테이너 내부의 `/tmp/` 폴더로 복사한다.

```bash
docker exec -it my-pg psql -U postgres -f //tmp/kant_shop.sql
```

복사한 SQL 파일을 PostgreSQL에서 실행한다.

| 부분 | 설명 |
|---|---|
| `docker cp` | 파일 복사 |
| `docker exec` | 실행 중인 컨테이너에서 명령어 실행 |
| `-it` | 터미널 입출력 연결 |
| `psql` | PostgreSQL 명령줄 도구 |
| `-U postgres` | postgres 사용자로 접속 |
| `-f` | SQL 파일 실행 |

**오류 해결 기록:** Git Bash에서 `/tmp/` 경로가 Windows 경로로 자동 변환되는 문제가 있었다. `/tmp` 앞에 슬래시 하나를 더 붙여 `//tmp`로 실행하는 방법으로 해결했다.

### 두 번째 방법 — SQL 파일 내용 직접 전달

```bash
docker exec -i my-pg psql -U postgres < kant_shop.sql
```

`<`는 파일의 내용을 명령어의 표준 입력으로 전달하는 기호다.

이 방법은 SQL 파일을 컨테이너 내부로 복사하지 않아도 된다.

### 두 방법의 차이

| 구분 | 방법 1 | 방법 2 |
|---|---|---|
| 파일 복사 | 필요 | 불필요 |
| 실행 방식 | `psql -f` | `<` 입력 리다이렉션 |
| 파일 위치 | 컨테이너 내부 | 내 컴퓨터 |

## 5. 데이터베이스 접속 및 조회

### 데이터베이스에 접속하기

```bash
docker exec -it my-pg psql -U postgres -d kant_shop
```

`-d kant_shop`은 접속할 데이터베이스 이름을 지정한다.

### 상품 목록 조회

```sql
SELECT * FROM product;
```

- `SELECT`: 데이터 조회
- `*`: 모든 열
- `FROM`: 조회할 테이블 지정
- `product`: 테이블 이름

### 터미널에서 SQL 한 번에 실행하기

```bash
docker exec -it my-pg psql -U postgres -d kant_shop -c "SELECT * FROM product"
```

`-c`는 SQL 명령어를 직접 전달하여 실행하는 옵션이다.

## 6. Docker Volume — 데이터 유지하기

### 볼륨이 필요한 이유

Docker 컨테이너를 삭제하면 컨테이너 내부에만 저장된 데이터도 사라질 수 있다.

**Docker Volume은 컨테이너와 별도로 데이터를 저장하는 공간**이다.

닌텐도에 비유하면 게임 칩으로 실행한 게임과 별개로 보관하는 세이브 데이터와 비슷하다.

```text
컨테이너 → 프로그램 실행 환경
볼륨     → 별도의 데이터 저장 공간
```

### 볼륨 명령어

```bash
docker volume ls
```

볼륨 목록 확인

```bash
docker volume create pgdata
```

`pgdata`라는 이름의 볼륨 생성

```bash
docker volume inspect pgdata
```

볼륨의 상세 정보 확인

### 볼륨을 연결한 PostgreSQL 컨테이너 생성

```bash
docker run -d --name my-pg -e POSTGRES_PASSWORD=admin1234 -p 5432:5432 -v pgdata:/var/lib/postgresql postgres:18
```

새롭게 추가한 옵션:

```bash
-v pgdata:/var/lib/postgresql
```

- `-v`: 볼륨 연결
- `pgdata`: 볼륨 이름
- `/var/lib/postgresql`: PostgreSQL 18 컨테이너의 데이터 저장 경로

### 컨테이너 중지 및 삭제

```bash
docker stop my-pg
```

컨테이너 중지

```bash
docker rm -f my-pg
```

컨테이너 강제 삭제

컨테이너를 삭제하더라도 별도로 생성한 `pgdata` 볼륨은 유지된다.

**핵심:** 컨테이너를 새로 만들고 같은 볼륨을 연결하면 기존 데이터를 다시 사용할 수 있다.

## 7. Docker Compose — compose.yaml 작성

오후에는 `docker run` 명령어에 작성했던 실행 설정을 `compose.yaml` 파일로 관리하는 방법을 배웠다.

### Docker CLI와 Compose 차이

| 구분 | Docker CLI | Docker Compose |
|---|---|---|
| 설정 방식 | 명령어에 직접 입력 | YAML 파일에 설정 작성 |
| 실행 | `docker run` | `docker compose up` |
| 특징 | 개별 컨테이너 실행 | 여러 서비스 설정을 하나의 파일로 관리 |

### 최종 compose.yaml

```yaml
services:
  db:
    image: postgres:18
    container_name: kant-pg
    environment:
      POSTGRES_PASSWORD: admin1234
    ports:
      - "5433:5432"
    volumes:
      - pgdata:/var/lib/postgresql

volumes:
  pgdata:
    external: true
```

### YAML 설정 설명

| 항목 | 의미 |
|---|---|
| `services` | 실행할 서비스 목록 |
| `db` | 서비스 이름 |
| `image` | 사용할 이미지 |
| `container_name` | 컨테이너 이름 |
| `environment` | 환경변수 설정 |
| `ports` | 포트 연결 |
| 서비스 내부 `volumes` | 컨테이너에 볼륨 연결 |
| 최상위 `volumes` | 사용할 볼륨 선언 |
| `external: true` | 이미 생성된 볼륨 사용 |

### 포트 변경

```yaml
ports:
  - "5433:5432"
```

- `5433`: 호스트(내 컴퓨터) 포트
- `5432`: 컨테이너 내부 PostgreSQL 포트

기존 5432번 호스트 포트와 충돌하지 않도록 호스트 쪽 포트를 5433으로 변경했다.

### external: true

```yaml
volumes:
  pgdata:
    external: true
```

오전에 만들었던 `pgdata` 볼륨을 재사용하기 위한 설정이다.

볼륨이 없다면 오류가 발생한다.

### Docker Compose 실행

```bash
docker compose up -d
```

실제 실행 결과:

```text
[+] up 2/2
✔ Network pg_lab_default Created
✔ Container kant-pg Started
```

- `Network pg_lab_default Created`: Compose의 기본 네트워크 생성
- `Container kant-pg Started`: PostgreSQL 컨테이너 시작

### 기존 데이터 조회

```bash
docker exec -it kant-pg psql -U postgres -d kant_shop -c "SELECT * FROM product"
```

실제 출력:

```text
 id |     name      | price  | stock
----+---------------+--------+-------
  1 | 무선이어폰    |  35000 |   100
  2 | 게이밍 마우스 |  28000 |    85
  3 | 27인치 모니터 | 259000 |    15
  4 | USB-C 허브    |  19900 |   200
  5 | 노트북 거치대 |  24000 |     7
(5 rows)
```

**확인한 결과:** 기존 `my-pg` 컨테이너와 다른 `kant-pg` 컨테이너를 실행했지만, 같은 `pgdata` 볼륨을 사용해 상품 5개를 그대로 조회할 수 있었다.

## 8. VS Code DBCode 설치 및 PostgreSQL 연결

### DBCode란?

VS Code에서 데이터베이스에 접속하고 테이블을 시각적으로 확인할 수 있는 확장 프로그램이다.

DBCode는 데이터베이스 서버 자체가 아니라 **기존 데이터베이스에 연결하는 클라이언트**다.

### 수업에서 사용한 연결 주소

```text
Host: localhost
Port: 5433
```

`localhost`는 내 컴퓨터를 의미한다.

`5433`은 Docker Compose에서 지정한 호스트 포트다.

### 연결 구조

```text
VS Code
   ↓
DBCode
   ↓
localhost:5433
   ↓
Docker 포트 연결
   ↓
kant-pg 컨테이너 (5432)
   ↓
PostgreSQL
   ↓
kant_shop 데이터베이스
   ↓
public 스키마
   ↓
product 테이블
   ↓
상품 데이터 5개
```

### 실습 결과

DBCode 탐색기에서 `kant_shop` 데이터베이스의 `public` 스키마와 `product` 테이블을 확인했다.

테이블을 열어 오전에 입력한 상품 5개가 그대로 표시되는 것을 확인했다.

## 9. 오늘 헷갈렸던 부분과 주의사항

### ① Docker 이미지와 컨테이너

- 이미지: 닌텐도 게임 칩처럼 실행에 필요한 원본
- 컨테이너: 그 칩을 바탕으로 실행한 게임에 비유
- 볼륨: 별도로 보관하는 세이브 데이터에 비유

### ② PostgreSQL과 SQL

- PostgreSQL: 데이터를 관리하는 프로그램
- SQL: 그 프로그램에 명령을 내리는 언어

### ③ 컨테이너 이름 변경

오전 컨테이너 이름은 `my-pg`, 오후 Compose 컨테이너 이름은 `kant-pg`였다.

`docker exec`를 사용할 때 실제 대상 컨테이너 이름을 정확히 입력해야 한다.

### ④ 포트 변경

오전에는 `5432:5432`, 오후에는 `5433:5432`를 사용했다.

컨테이너 내부 PostgreSQL 포트는 동일하지만 호스트 포트가 달라졌다.

### ⑤ 데이터 삭제 주의

`docker rm`으로 컨테이너를 삭제하는 것과 `DROP DATABASE`로 데이터베이스를 삭제하는 것은 다르다.

볼륨이 있어도 SQL로 데이터베이스를 삭제하면 데이터가 사라진다.

### ⑥ 수업 내용과 별도 오류 해결 구분

Git Bash의 경로 자동 변환 문제 때문에 `/tmp` 대신 `//tmp`를 사용한 해결 방법을 기록했다.

그 과정에서 별도로 제안받았던 `MSYS_NO_PATHCONV=1` 설정은 오늘 튜터님이 가르친 명령어가 아니므로 SQL 실습 명령어 목록에 포함하지 않았다.

Docker로 PostgreSQL을 실행하고, SQL로 데이터를 생성·조회한 다음, Docker 볼륨으로 데이터를 유지하고 Compose와 DBCode로 데이터베이스를 관리하는 전체 과정을 실습했다.
전체적인 흐름을 이해하는데 중점을 뒀다. 지금 배운 내용만으로는 sql을 어느정도 이해했다고 할 수 있는지도 모르겠다. 추후에 다시 학습한다고 하니 지금 당장 100퍼 센트를 이해하려고 하지는 말자.

**오늘 가장 중요하게 이해한 것은 실행 환경(Docker), 데이터 관리(PostgreSQL), 명령어(SQL), 데이터 보관(Volume), 실행 설정(Compose)이 서로 다른 역할을 한다는 점이다.**
