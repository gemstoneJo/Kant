# 2026.11.12 — Day 14 TIL | Docker 기초와 데이터베이스

## 1. 오늘의 학습 내용과 전체 흐름

오늘은 **Docker를 이용해 프로그램 실행 환경을 만들고 관리하는 방법**을 배웠다. `hello-world`로 기본 실행을 확인한 뒤 Ubuntu 컨테이너의 터미널에 들어가 파일을 만들었고, Nginx 웹서버를 실행해 웹페이지를 확인하고 수정했다. 이후 MySQL과 PostgreSQL 데이터베이스 서버를 컨테이너로 실행하고 접속했다.

**전체 흐름**

```text
Docker 설치·상태 확인
  ↓
이미지 다운로드 (pull)
  ↓
컨테이너 생성 및 실행 (run)
  ↓
실행 상태 확인 (ps)
  ↓
컨테이너 내부 작업 (exec 또는 대화형 run)
  ↓
웹 요청·DB 접속 테스트 / 로그 확인
  ↓
컨테이너 중지 (stop) → 삭제 (rm)
```

**오늘의 핵심:** Docker는 프로그램 자체를 새로 개발하는 언어가 아니라, 프로그램이 실행되는 환경을 **이미지와 컨테이너**로 관리하는 도구다.

## 2. 처음 배우는 용어

| 용어 | 뜻 | 오늘의 예시 |
| --- | --- | --- |
| Docker | 프로그램을 격리된 환경에서 실행·관리하는 도구 | Ubuntu, Nginx, MySQL 실행 |
| Docker Engine | 이미지와 컨테이너를 실제로 관리하는 핵심 서비스 | `docker info`로 정보 확인 |
| 이미지(Image) | 프로그램과 실행에 필요한 파일을 담은 템플릿 | `nginx`, `ubuntu:24.04` |
| 컨테이너(Container) | 이미지를 바탕으로 생성한 실행 환경 | `my-server`, `my-webserner` |
| 호스트(Host) | Docker를 실행하는 내 컴퓨터 또는 서버 | Git Bash에서 Docker 명령 실행 |
| 터미널(Terminal) | 명령어를 입력하는 창 | VS Code 터미널, Git Bash |
| CLI | 명령줄로 프로그램을 조작하는 방식 | `docker ps` |
| Shell / Bash | 명령어를 해석하고 실행하는 프로그램 | Ubuntu 컨테이너의 `bash` |
| Ubuntu | Linux 배포판의 하나 | `ubuntu:24.04` |
| Nginx | 웹 요청을 처리하는 웹서버 | `localhost:8080` 접속 |
| HTTP | 브라우저와 서버가 요청·응답을 주고받는 규칙 | `curl localhost:8080` |
| localhost | 현재 사용 중인 컴퓨터를 가리키는 주소 | `localhost:8080` |
| 포트(Port) | 네트워크 프로그램을 구별하는 번호 | 8080, 80, 3306, 5432 |
| 데이터베이스(DB) | 데이터를 체계적으로 저장·관리하는 공간 | `shop` 데이터베이스 |
| DBMS | 데이터베이스를 관리하는 프로그램 | MySQL, PostgreSQL |
| SQL | DB에 조회·생성·수정·삭제를 요청하는 언어 | `CREATE DATABASE shop;` |
| 로그(Log) | 프로그램 실행 상태와 오류 기록 | `docker logs` |
| 환경변수 | 실행 프로그램에 전달하는 설정값 | `MYSQL_ROOT_PASSWORD` |
| Volume | 컨테이너와 별도로 데이터를 저장하는 공간 | DB 데이터 보존에 사용 |
| 태그(Tag) | 이미지 버전 등을 구별하는 표시 | `mysql:8.4`, `postgres:18` |

### 이미지와 컨테이너의 차이

- **이미지**: 실행에 필요한 파일과 설정을 담은 **설계도/템플릿**.
- **컨테이너**: 이미지를 기반으로 실제 생성한 **실행 공간**.
- 하나의 이미지로 여러 컨테이너를 만들 수 있다.
- `docker pull`은 이미지만 준비하고, `docker run`은 새 컨테이너를 만든다.
- `docker start`는 **이미 만들어진 컨테이너**를 다시 시작한다.

```text
이미지: nginx
   ├── 컨테이너 A
   └── 컨테이너 B

이미지: mysql:8.4
   └── 컨테이너 my-sql
```

> 컨테이너는 컴퓨터 전체를 새로 만드는 가상머신과는 다르다. 운영체제의 커널을 공유하면서 프로세스를 격리하는 방식이다.

## 3. Docker 명령어 전체 정리 — 기능과 사용하는 이유

| 명령어 | 기능 | 언제 사용하는가? |
| --- | --- | --- |
| `docker --version` | Docker CLI 버전 확인 | 설치 여부 확인 |
| `docker compose version` | Docker Compose 버전 확인 | 여러 컨테이너 관리 기능 확인 |
| `docker info` | Docker 엔진 및 환경 정보 | Docker가 동작하는지 점검 |
| `docker pull 이미지` | 이미지 다운로드 | 실행할 프로그램 준비 |
| `docker images` | 다운로드된 이미지 목록 | 어떤 이미지가 있는지 확인 |
| `docker image ls` | 이미지 목록 확인 | `docker images`와 같은 용도 |
| `docker run 이미지` | 새 컨테이너 생성·실행 | 프로그램을 처음 실행할 때 |
| `docker ps` | 실행 중인 컨테이너 조회 | 서버가 살아 있는지 확인 |
| `docker ps -a` | 종료된 컨테이너까지 조회 | 중지된 컨테이너 찾기 |
| `docker start 이름` | 기존 컨테이너 시작 | 종료된 컨테이너 재실행 |
| `docker start -ai 이름` | 기존 컨테이너 시작 후 입출력 연결 | Ubuntu Bash 실습 이어서 하기 |
| `docker exec -it 이름 bash` | 실행 중 컨테이너에서 Bash 실행 | 컨테이너 내부 파일 확인·수정 |
| `docker logs 이름` | 컨테이너 로그 조회 | 서버 오류와 요청 기록 확인 |
| `docker logs -f 이름` | 새 로그를 계속 출력 | 실시간 상태 확인 |
| `docker stop 이름` | 실행 중인 컨테이너 중지 | 서버를 멈출 때 |
| `docker rm 이름` | 컨테이너 삭제 | 필요 없는 컨테이너 정리 |
| `docker rmi 이미지` | 이미지 삭제 | 필요 없는 이미지 정리 |
| `docker rmi -f 이미지` | 이미지 강제 제거 | 일반 삭제가 안 될 때 원인 확인 후 신중히 사용 |

### 옵션 정리

| 옵션 | 뜻 | 예시 |
| --- | --- | --- |
| `-i` | 표준 입력 유지 | `docker run -it ...` |
| `-t` | 터미널 할당 | `docker run -it ...` |
| `-it` | 직접 명령을 입력하는 대화형 실행 | Ubuntu Bash 접속 |
| `-d` | 백그라운드 실행 | Nginx·DB 서버 실행 |
| `--name` | 컨테이너 이름 지정 | `--name my-server` |
| `-p 호스트:컨테이너` | 두 포트를 연결 | `-p 8080:80` |
| `-e 이름=값` | 환경변수 전달 | DB 초기 비밀번호 설정 |
| `-a` | 명령에 따라 의미가 다름 | `ps -a`: 전체 조회 / `start -a`: 출력 연결 |
| `-f` | 명령에 따라 의미가 다름 | `logs -f`: 실시간 추적 / `rmi -f`: 강제 삭제 |

**가장 헷갈리기 쉬운 세 가지**

```text
run   = 새 컨테이너 만들고 실행
start = 기존 컨테이너 다시 실행
exec  = 실행 중인 컨테이너 안에서 추가 명령 실행
```

## 4. 실습 ① Hello World — 이미지와 컨테이너 확인

```bash
docker --version
docker compose version
docker info

docker pull hello-world
docker run hello-world

docker ps
docker ps -a
docker image ls
docker images
```

- `docker pull hello-world`: 테스트용 이미지 다운로드.
- `docker run hello-world`: 컨테이너를 생성하고 안내 메시지를 출력한 뒤 종료.
- `docker ps`: 실행이 끝난 컨테이너는 표시되지 않을 수 있음.
- `docker ps -a`: 종료된 컨테이너도 확인 가능.

삭제 실습:

```bash
docker rm 컨테이너ID
docker rmi hello-world
```

**주의:** `docker rm`은 **컨테이너** 삭제, `docker rmi`는 **이미지** 삭제. 수업에서 `docker rmi hello-world -f`도 시도했지만 해당 명령의 성공 여부와 강제 삭제가 필요했던 이유는 기록만으로 확정할 수 없다.

**오류:** `hello-wordl`이라고 입력한 부분은 `hello-world`의 오타.

## 5. 실습 ② Ubuntu — 컨테이너 안에서 Linux 사용

### 이미지 다운로드 및 실행

```bash
docker pull ubuntu:24.04
docker run -it --name my-server ubuntu:24.04 bash
```

명령어를 부분별로 해석하면:

- `docker run`: 새 컨테이너 생성·실행.
- `-it`: 직접 키보드로 명령을 입력할 수 있도록 터미널 연결.
- `--name my-server`: 컨테이너 이름을 `my-server`로 지정.
- `ubuntu:24.04`: 사용할 이미지와 버전.
- `bash`: 컨테이너 안에서 실행할 셸.

### 컨테이너 내부에서 실행한 명령어

```bash
ls -al
cd /etc
cat os-release
```

| 명령어 | 의미 |
| --- | --- |
| `ls -al` | 숨김 파일을 포함해 파일·폴더 자세히 보기 |
| `cd /etc` | `/etc` 폴더로 이동 |
| `cat os-release` | 운영체제 정보 파일 읽기 |
| `pwd` | 현재 위치 확인 |
| `exit` | 현재 셸 종료 |

실제 출력에서 **Ubuntu 24.04.5 LTS**를 확인했다. `apt update`도 시도했지만 `Ctrl+C`로 중단했으므로 정상 완료한 것으로 기록하지 않는다.

### 파일 만들기와 재시작

```bash
# Ubuntu 컨테이너 내부
echo '# Hello Docker' > README.md
exit

# 호스트 터미널
docker ps -a
docker start -ai my-server
```

같은 컨테이너를 재시작하니 만든 `README.md`가 남아 있었다.

- **중지 후 재시작**: 같은 컨테이너의 쓰기 계층이 남아 있어 파일 변경 유지.
- **삭제 후 새로 생성**: 기존 컨테이너의 쓰기 계층은 사라짐.

실습 후 컨테이너 ID로 `docker rm 29670ea34604`를 실행했다.

### 실제 오류

```bash
# 잘못된 명령
docker run -it my-server ubuntu:24.04 bash
docker run -it --my-server ubuntu:24.04 bash

# 올바른 명령
docker run -it --name my-server ubuntu:24.04 bash
```

`my-server`를 컨테이너 이름으로 쓰려면 반드시 `--name` 옵션이 필요하다.

## 6. 실습 ③ Nginx — 웹서버 실행과 포트 연결

### Nginx란?

Nginx는 브라우저 등의 HTTP 요청에 응답해 웹페이지를 제공하거나 다른 서버에 요청을 전달할 수 있는 웹서버다.

### 실행

```bash
docker pull nginx
docker run -d --name my-webserner -p 8080:80 nginx
docker ps
curl localhost:8080
```

> **실습 기록 주의:** 실제 생성한 이름은 오타가 포함된 `my-webserner`였다. 아래 명령도 실제 이름에 맞춰 기록한다. 새 실습에서는 `my-webserver`처럼 정확한 이름을 권장한다.

### `-p 8080:80` 구조

```text
내 컴퓨터(호스트)
브라우저 또는 curl
       │
       │ http://localhost:8080
       ▼
호스트의 8080 포트
       │ Docker 포트 연결(-p 8080:80)
       ▼
Nginx 컨테이너의 80 포트
       │
       ▼
Nginx가 HTML 응답
```

- **왼쪽 `8080`**: 내 컴퓨터에서 접속할 포트.
- **오른쪽 `80`**: 컨테이너 안에서 Nginx가 요청을 받는 포트.
- `curl localhost:8080`: 브라우저 대신 터미널에서 HTTP 요청을 보내 웹서버가 응답하는지 확인.
- `docker ps`에서 `Up`, `0.0.0.0:8080->80/tcp`가 표시되어 실행 및 연결 상태를 확인했다.

### Nginx 내부 HTML 수정

```bash
# 호스트 터미널
docker exec -it my-webserner bash

# Nginx 컨테이너 내부
cd /usr/share/nginx/html
cat index.html
echo '<h1>hello docker</h1>' > index.html
cat index.html
exit
```

- `docker exec`: **이미 실행 중인** Nginx 컨테이너에서 새 명령을 실행.
- `/usr/share/nginx/html/index.html`: Nginx 기본 웹페이지 파일 위치.
- `>`: 파일 내용을 **덮어쓰기**. `>>`는 기존 내용 뒤에 추가.

### 로그 확인

```bash
# 반드시 Docker 관리 명령이 동작하는 호스트 터미널에서 실행
docker logs my-webserner
docker logs -f my-webserner
```

로그에서 관찰한 HTTP 상태 코드:

| 코드 | 의미 | 오늘 확인한 사례 |
| --- | --- | --- |
| `200` | 요청 성공 | `/` 페이지 응답 |
| `301` | 다른 주소로 이동 안내 | `curl http://google.co.kr` 결과 |
| `304` | 캐시된 내용 사용 가능 | 반복 웹 요청 |
| `404` | 요청한 경로가 없음 | `/favicon.ico`, `/admin` |

**오류와 해결**

1. `docker exec -it my-webserver bash` → 실제 이름은 `my-webserner`여서 `No such container` 발생.
2. `cd user` → 해당 디렉터리가 없어 실패. 실제 경로의 `usr`로 이동해야 함.
3. `echo "<h1>Hello Docker!!!</h1>" > index.html` → Bash에서 `!`가 히스토리 확장으로 해석되어 `event not found`. **작은따옴표**로 감싸면 방지할 수 있음.
4. 컨테이너 안에서 `docker logs` → `docker: command not found`. Docker 관리 명령은 호스트에서 실행.
5. `lsof -i:8080` → 오늘 Git Bash에는 `lsof`가 없어 실패. `netstat -ano | grep :8080`으로 포트 상태 확인.

실습 후 `docker stop`과 `docker rm`으로 Nginx 컨테이너를 중지·삭제했다.

## 7. 실습 ④ MySQL — 데이터베이스 서버 실행

### 데이터베이스와 MySQL이란?

- **데이터베이스(DB)**: 회원, 상품, 주문 등 데이터를 체계적으로 저장하는 곳.
- **MySQL**: 관계형 데이터베이스를 관리하는 프로그램(DBMS).
- **SQL**: MySQL에 데이터를 조회하거나 데이터베이스를 생성하도록 요청하는 언어.

### Docker에서 MySQL 실행

```bash
docker pull mysql:8.4
docker run -d --name my-sql -e MYSQL_ROOT_PASSWORD=admin1234 -p 3306:3306 mysql:8.4
docker logs -f my-sql
docker exec -it my-sql mysql -uroot -p
```

| 부분 | 설명 |
| --- | --- |
| `mysql:8.4` | MySQL 8.4 이미지 |
| `--name my-sql` | 컨테이너 이름 |
| `-e MYSQL_ROOT_PASSWORD=...` | MySQL 관리자 초기 비밀번호 전달 |
| `-p 3306:3306` | 호스트 3306과 컨테이너 3306 연결 |
| `mysql -uroot -p` | MySQL 클라이언트로 root 계정 접속, 비밀번호 입력 |
| `docker logs -f my-sql` | DB 서버 시작·오류 로그 확인 |

수업 로그에서 MySQL 서버가 `ready for connections` 상태에 도달한 것을 확인했다.

### MySQL 접속 후 SQL 명령어

```sql
SHOW DATABASES;
CREATE DATABASE shop;
SHOW DATABASES;
```

- `SHOW DATABASES;`: 데이터베이스 목록 조회.
- `CREATE DATABASE shop;`: `shop`이라는 새 데이터베이스 생성.
- `;`: SQL 문장의 끝을 나타내는 구분자.

수업에서는 `shop` 데이터베이스가 생성된 것을 확인했다.

### 삭제와 데이터 보존의 차이

MySQL 컨테이너를 삭제한 뒤 새로 실행했을 때 새 컨테이너에서는 `shop` 데이터베이스가 보이지 않았다.

**정확한 이해:** 컨테이너 삭제가 곧 모든 데이터의 완전 삭제를 뜻하는 것은 아니다. MySQL 공식 이미지는 데이터 저장용 볼륨을 사용할 수 있다. 이전 데이터가 저장된 볼륨이 남아 있을 수 있지만, 새 컨테이너에 자동으로 연결되지 않을 수 있다. 실제 프로젝트에서는 **이름 있는 볼륨(named volume)** 등을 명시적으로 사용한다.

```bash
# 학습용 예시: 명시적인 볼륨을 연결해 MySQL 데이터 저장
docker volume create mysql-data
docker run -d --name my-sql-persist \
  -e MYSQL_ROOT_PASSWORD=example-password \
  -p 3307:3306 \
  -v mysql-data:/var/lib/mysql \
  mysql:8.4
```

> 위 코드는 **오늘 직접 실행한 명령이 아니라 추가 학습 예시**다. 실습 비밀번호를 실제 운영에 재사용하지 말고, 운영 환경에서는 비밀정보를 명령줄에 직접 노출하지 않도록 관리한다.

### MySQL 실습 오류

- `docker logs -sql`: 잘못된 옵션. 올바른 형태는 `docker logs -f my-sql` 또는 `docker logs my-sql`.
- `!119`, `!123`: Docker 명령이 아니라 **Bash 히스토리의 해당 번호 명령을 재실행**하는 기능. 실행 전에 `history`로 내용 확인.

## 8. 실습 ⑤ PostgreSQL — 또 다른 데이터베이스

PostgreSQL도 MySQL과 같은 **관계형 데이터베이스 관리 시스템**이다. Docker로 실행하는 원리는 같다.

```bash
docker pull postgres:18
docker run -d --name my-pg -e POSTGRES_PASSWORD=admin1234 -p 5432:5432 postgres:18
docker logs my-pg
docker exec -it my-pg psql -U postgres
```

PostgreSQL 클라이언트(`psql`)에 접속한 뒤:

```text
\l
\q
```

- `\l`: 데이터베이스 목록 조회.
- `\q`: `psql` 종료.
- `\l`과 `\q`는 일반 SQL이 아니라 **psql 클라이언트 전용 명령어**다.
- 수업 로그에서 서버의 `ready to accept connections` 상태와 기본 데이터베이스 목록을 확인했다.

| 구분 | MySQL | PostgreSQL |
| --- | --- | --- |
| 이미지 | `mysql:8.4` | `postgres:18` |
| 기본 포트 | `3306` | `5432` |
| 초기 비밀번호 환경변수 | `MYSQL_ROOT_PASSWORD` | `POSTGRES_PASSWORD` |
| 접속 프로그램 | `mysql` | `psql` |
| 데이터베이스 목록 | `SHOW DATABASES;` | `\l` (`psql` 명령) |

## 9. SQL 기초 — 오늘 처음 배운 개념

SQL은 **Structured Query Language(구조화 질의 언어)**의 약자다. 데이터베이스에 명령을 전달할 때 사용한다.

### Docker / MySQL / SQL 구분

| 구분 | 역할 |
| --- | --- |
| Docker | MySQL 서버를 컨테이너로 실행하고 관리 |
| MySQL | 실제 데이터를 저장하고 관리 |
| SQL | MySQL에 데이터 작업을 요청 |
| Python | 애플리케이션의 기능과 동작 구현. 필요하면 DB에 SQL 요청 |

### 자주 사용하는 SQL

| SQL 명령 | 기능 | 예시 상황 |
| --- | --- | --- |
| `SELECT` | 데이터 조회 | 상품 목록 보기 |
| `INSERT` | 데이터 추가 | 회원 등록 |
| `UPDATE` | 데이터 수정 | 상품 가격 변경 |
| `DELETE` | 데이터 삭제 | 주문 삭제 |
| `CREATE DATABASE` | 데이터베이스 생성 | `shop` 만들기 |

다음은 **오늘 실습에서 직접 실행한 코드가 아니라 SQL 이해를 위한 예시**다. `products` 테이블이 이미 존재한다고 가정한다.

```sql
-- 상품 조회
SELECT * FROM products;

-- 상품 추가
INSERT INTO products (name, price)
VALUES ('키보드', 50000);

-- 상품 가격 수정
UPDATE products
SET price = 45000
WHERE id = 1;

-- 상품 삭제
DELETE FROM products
WHERE id = 1;
```

**주의:** `UPDATE`, `DELETE`에서 `WHERE`를 빠뜨리면 여러 행이 한꺼번에 수정·삭제될 수 있다.

## 11. 실무에서는 언제 사용하는가?

### 예시 1: Python 쇼핑몰 프로그램

```text
Python 쇼핑몰 API
       │ SQL로 상품 정보 요청
       ▼
MySQL 또는 PostgreSQL 컨테이너
       │
       ▼
회원·상품·주문 데이터 저장
```

- 개발자는 Docker로 DB 서버를 쉽게 실행한다.
- Python 프로그램은 DB에 접속해 SQL로 데이터를 조회·수정한다.
- 데이터가 중요하므로 볼륨이나 외부 DB 저장소를 사용한다.

### 예시 2: 웹서비스

```text
사용자 브라우저
      ↓ HTTP 요청
Nginx
      ↓ 필요시 요청 전달
Python 웹 애플리케이션
      ↓ 데이터 조회
MySQL / PostgreSQL
```

이 구조는 **앞으로 배우게 될 수 있는 실무 활용 예시**이며, 오늘 Nginx와 Python을 직접 연결한 실습은 아니다.

### 예시 3: 서버가 작동하지 않을 때

1. `docker ps`: 컨테이너가 실행 중인가?
2. `docker ps -a`: 종료된 컨테이너가 있는가?
3. `docker logs 컨테이너명`: 오류가 무엇인가?
4. `docker exec -it 컨테이너명 bash`: 내부 파일·설정을 확인할 수 있는가? (컨테이너에 Bash가 있는 경우)
5. `docker stop` / `docker start`: 필요한 경우 서버 재시작.

## 13. 오늘의 핵심 암기

```text
pull  → 이미지 준비
run   → 새 컨테이너 생성·실행
ps    → 실행 상태 확인
exec  → 실행 중인 컨테이너 내부에서 명령 실행
logs  → 프로그램 기록 확인
stop  → 컨테이너 중지
rm    → 컨테이너 삭제
rmi   → 이미지 삭제
```

**특히 기억할 4가지**

1. **이미지 ≠ 컨테이너**: 이미지는 템플릿, 컨테이너는 실제 실행 공간.
2. **`run` ≠ `start` ≠ `exec`**: 새로 만들기 / 다시 시작 / 실행 중인 곳에 명령 추가.
3. **`-p 8080:80`**: 호스트 포트가 왼쪽, 컨테이너 포트가 오른쪽.
4. **Docker ≠ MySQL ≠ SQL**: 실행 환경 관리 / DB 관리 프로그램 / DB에 요청하는 언어.
