## 2. 다마고치 프로젝트 복습

어제 오전에 진행한 다마고치 프로젝트를 복습했다.

### 2-1. 프로젝트 파일 구조

```text
tamagotchi/
├── config.py
├── pet.py
└── main.py
```

| 파일 | 역할 |
|---|---|
| `config.py` | 게임에서 사용할 초기 설정값 관리 |
| `pet.py` | 반려동물의 상태와 행동을 정의 |
| `main.py` | 반려동물 객체를 생성하고 프로그램 실행 |

**핵심:** 하나의 파일에 모든 코드를 작성하지 않고, 역할에 따라 파일을 분리한다.

### 2-2. config.py

```python
START_HUNGER = 30
START_HAPPY = 70
START_ENERGY = 70
```

반려동물의 초기 상태를 상수로 관리한다.

- `START_HUNGER`: 초기 배고픔
- `START_HAPPY`: 초기 행복도
- `START_ENERGY`: 초기 에너지

상수를 별도 파일에 관리하면 초기 설정을 수정할 때 여러 파일을 찾아다닐 필요가 없다.

### 2-3. pet.py

`Pet` 클래스를 정의하는 파일이다.

주요 구성 요소:

| 구성 요소 | 역할 |
|---|---|
| `Pet.count` | 클래스 차원의 공통 변수 |
| `__init__()` | 객체 생성 시 초기 상태 설정 |
| `__str__()` | 객체를 문자열로 표현 |
| `mood()` | 현재 기분 판단 |
| `bar()` | 상태를 시각적으로 표현 |
| `_clamp()` | 상태값의 범위 제한 |
| `_change()` | 상태값 변경을 처리하는 내부 메서드 |
| `feed()` | 먹이 주기 |
| `play()` | 놀아주기 |
| `sleep()` | 잠자기 |
| `pass_time()` | 시간 경과에 따른 상태 변경 |

#### 클래스 변수와 인스턴스 변수

```python
class Pet:
    count = 0

    def __init__(self, name):
        self.name = name
```

- `count`: 클래스에 속하는 변수
- `self.name`: 생성된 객체마다 독립적으로 가지는 변수

`self`는 현재 메서드를 호출한 객체를 가리킨다.

#### 언더스코어(_)의 의미

`_clamp()`, `_change()`처럼 이름 앞에 `_`가 붙은 메서드는 내부 구현에 사용한다는 관례를 나타낸다.

Python에서 접근 자체를 막는 기능은 아니지만, 외부에서 직접 사용하기보다는 클래스 내부에서 사용하는 용도로 구분한다.

### 2-4. main.py

```python
from pet import Pet

choco = Pet("초코")
print(choco)
```

실행 흐름:

1. `pet.py`에서 `Pet` 클래스를 가져온다.
2. `Pet("초코")`로 객체를 생성한다.
3. 생성된 객체를 `choco` 변수에 저장한다.
4. `print(choco)`를 실행하면 `__str__()`에서 정의한 문자열 표현을 사용한다.

### 2-5. __name__과 __main__

```python
if __name__ == "__main__":
    print("직접 실행했을 때만 실행")
```

| 실행 방법 | `__name__` 값 |
|---|---|
| 해당 파일을 직접 실행 | `"__main__"` |
| 다른 파일에서 import | 모듈 이름 |

이 조건문을 사용하면 다른 파일에서 클래스를 가져올 때 테스트 코드가 불필요하게 실행되는 것을 방지할 수 있다.

## 3. 쇼핑몰 장바구니 프로젝트

오늘의 주요 Python 학습 내용이다.


예를 들어:

| 상품 합계 | 배송비 | 최종 금액 |

| 20,000원 | 유료 | 상품 합계 + 배송비 |
| 30,000원 | 무료 | 30,000원 |
| 50,000원 | 무료 | 50,000원 |

### 3-5. checkout()과 재고 관리

결제 시 장바구니에 담긴 상품 수량만큼 상품의 재고를 감소시킨다.

결제 처리 이후에는 장바구니를 비운다.

여기서 중요한 점은 **Cart가 Product 객체를 참조하고 있다는 것**이다.

따라서 Cart에서 Product의 재고를 변경하면 해당 상품 객체의 상태가 변경된다.

## 4. 쿠폰 클래스와 상속

### 4-1. 쿠폰 구조

```python
class Coupon:
    def discount_amount(self, amount):
        return 0


class PercentCoupon(Coupon):
    pass


class FixedCoupon(Coupon):
    pass
```

위 코드는 상속 관계를 이해하기 위한 간단한 예시다. 실제 오늘 작성한 `coupon.py`에는 각 쿠폰 클래스의 생성자와 할인 계산 메서드가 정의되어 있지만, 할인 계산 부분은 아직 `pass` 상태다.

### 4-2. 상속이란?

기존 클래스의 기능을 새로운 클래스에서 물려받는 것이다.

```python
class PercentCoupon(Coupon):
```

`PercentCoupon`은 `Coupon`을 상속받는다.

- `Coupon`: 부모 클래스
- `PercentCoupon`: 자식 클래스
- `FixedCoupon`: 자식 클래스

### 4-3. super().__init__()

```python
super().__init__(...)
```

부모 클래스의 `__init__()`을 호출한다.

부모 클래스에서 정의한 초기화 기능을 재사용할 수 있다.

**주의:** `super()`는 `self`와 같은 의미가 아니다.

- `self`: 현재 인스턴스에 접근할 때 사용
- `super()`: 부모 클래스의 메서드를 호출할 때 사용

### 4-4. 메서드 오버라이딩

부모 클래스에 정의된 메서드를 자식 클래스에서 같은 이름으로 다시 정의하는 것이다.

```python
class Coupon:
    def discount_amount(self, amount):
        return 0


class FixedCoupon(Coupon):
    def discount_amount(self, amount):
        return 1000
```

두 클래스 모두 `discount_amount()`라는 메서드를 가지고 있지만 동작은 다르다.

### 4-5. 오늘 코드의 미완성 부분

`PercentCoupon`, `FixedCoupon`의 `discount_amount()` 내부가 아직 `pass` 상태다.

```python
def discount_amount(self, amount):
    pass
```

`pass`는 아무 작업도 하지 않고 넘어가는 문장이다.

**중요:** `pass`가 있다고 해서 할인 계산 기능이 구현된 것은 아니다.

추후 할인율 계산, 정액 할인 계산, 최종 금액 적용 로직을 구현해야 한다.

## 5. Python 파일 간 연결과 import

### 5-1. import의 역할

다른 Python 파일에 정의된 클래스나 함수를 가져오는 기능이다.

```python
from product import Product
```

의미:

- `product`: 가져올 모듈 이름
- `Product`: 모듈 안에 정의된 클래스 이름

### 5-2. 파일 이름과 클래스 이름 구분

| 구분 | 예시 |
|---|---|
| 파일 이름 | `product.py` |
| 모듈 이름 | `product` |
| 클래스 이름 | `Product` |
| 객체 생성 | `Product(...)` |

### 5-3. import 시 주의할 점

파일 아래에 테스트 코드를 작성하면 다른 파일에서 import할 때도 해당 코드가 실행될 수 있다.

이를 방지하기 위해 다음 구조를 사용한다.

```python
if __name__ == "__main__":
    # 테스트 코드
    pass
```

오늘 `product.py`에는 이러한 실행 조건이 있었지만, `cart.py`의 테스트 코드는 파일 아래에 직접 작성되어 있었다.

따라서 `cart.py`를 다른 파일에서 가져올 경우 테스트 코드까지 실행될 수 있다는 점을 확인했다.

## 6. WSL 2와 Ubuntu 설치

### 6-1. WSL이란?

WSL(Windows Subsystem for Linux)은 Windows에서 Linux 환경을 실행할 수 있도록 지원하는 기능이다.

오늘 설치한 구성:

| 구성 요소 | 설치 버전 |
|---|---|
| Windows | 10.0.26200.9711 |
| WSL | 3.0.5.0 |
| Linux 커널 | 6.18.58.1-1 |
| Ubuntu | 26.04.1 LTS |

### 6-2. WSL과 Ubuntu의 차이

- **WSL:** Windows에서 Linux를 실행할 수 있도록 제공하는 기반 환경
- **Ubuntu:** WSL에서 실행하는 Linux 배포판

즉, WSL과 Ubuntu는 같은 프로그램이 아니다.

### 6-3. 설치 과정

처음에는 다음 명령어로 설치를 시도했다.

```powershell
wsl --install
```

추가로 시도한 명령어:

```powershell
wsl --install --web-download
wsl --update
```

그러나 설치 과정에서 `403` 오류가 발생했다.

#### 해결 과정

1. Windows의 가상 머신 플랫폼 기능 활성화
2. Microsoft WSL 공식 GitHub 배포 페이지에서 설치 파일 다운로드
3. `wsl.3.0.5.0.x64.msi` 설치
4. WSL 버전 확인
5. WSL 2를 기본 버전으로 지정
6. Ubuntu 배포판 설치
7. Ubuntu 사용자 계정 및 비밀번호 설정

가상 머신 플랫폼 활성화에 사용한 명령어:

```powershell
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
```

WSL 2 기본 버전 지정:

```powershell
wsl --set-default-version 2
```

Ubuntu 설치:

```powershell
wsl --install -d Ubuntu
```

### 6-4. 설치 확인

```powershell
wsl --version
```

확인된 결과:

```text
WSL 버전: 3.0.5.0
커널 버전: 6.18.58.1-1
```

Ubuntu에서도 다음 명령어로 배포판 정보를 확인했다.

```bash
cat /etc/os-release
```

확인된 내용:

```text
PRETTY_NAME="Ubuntu 26.04.1 LTS"
VERSION_ID="26.04"
VERSION_CODENAME=resolute
```

Ubuntu 설치와 실행은 정상적으로 확인했다.

단, `wsl -l -v` 명령어의 최종 출력은 아직 확인하지 않았으므로 Ubuntu가 WSL 2로 실행되는지는 마지막 검증이 필요하다.

## 7. 오늘 발생한 오류와 해결 방법

### 7-1. WSL 설치 중 403 오류

**현상:** WSL 설치 및 업데이트 과정에서 `403` 오류 발생

**해결:** 공식 GitHub 배포 파일을 직접 다운로드하여 WSL 설치

**배운 점:** 설치 명령어가 실패하더라도 공식 설치 파일을 통한 대체 설치 방법이 존재한다.

### 7-2. Ubuntu 비밀번호 입력 오류

```text
Sorry, passwords do not match.
```

**원인:** 비밀번호와 비밀번호 확인 입력이 일치하지 않음

Ubuntu에서는 비밀번호를 입력할 때 화면에 문자나 `*`가 나타나지 않는다.

입력이 되지 않는 것처럼 보여도 실제로는 키보드 입력이 처리된다.

**해결:** 같은 비밀번호를 두 번 입력하고 각각 Enter를 누른다.

### 7-3. wsl: command not found

Ubuntu 터미널에서 다음 명령어를 실행했다.

```bash
wsl -l -v
```

결과:

```text
wsl: command not found
```

**원인:** Windows에서 사용하는 `wsl` 명령어를 Ubuntu 내부에서 실행했기 때문이다.

**해결:** Ubuntu에서 `exit`로 나간 후 Windows PowerShell에서 실행한다.

```powershell
wsl -l -v
```

Ubuntu 안에서 Windows 실행 파일을 호출하는 경우에는 `wsl.exe`를 사용할 수도 있다.

## 10. 오늘의 핵심 개념 복습

### 객체지향 문법

| 문법 | 의미 |
|---|---|
| `class` | 클래스 정의 |
| `__init__()` | 객체 초기화 |
| `self` | 현재 인스턴스 참조 |
| `self.name` | 인스턴스 속성 접근 |
| `obj.method()` | 객체의 메서드 호출 |
| `super()` | 부모 클래스 기능 접근 |
| `__str__()` | 객체의 문자열 표현 |
| `import` | 다른 모듈 가져오기 |
| `__name__` | 모듈의 실행 이름 |
| `pass` | 아무 작업도 하지 않고 넘어감 |

### 특히 헷갈리지 말아야 할 부분

**점(`.`)과 괄호(`()`)의 차이**

```python
product.name
product.is_sold_out()
```

- `product.name`: 속성값에 접근
- `product.is_sold_out()`: 메서드를 호출

**self와 super()의 차이**

```python
self.name
super().__init__(...)
```

- `self`: 현재 객체
- `super()`: 부모 클래스의 메서드에 접근하기 위한 기능

**클래스와 객체의 차이**

```python
class Product:
    pass

item = Product()
```

- `Product`: 클래스
- `item`: 생성된 인스턴스를 참조하는 변수
