## 2. 객체지향 프로그래밍(OOP)

### 2-1. 클래스와 인스턴스

클래스는 데이터와 기능을 하나로 묶어 관리하는 구조다.

```python
class User:
    def __init__(self, name):
        self.name = name

    def show(self):
        print(self.name)

user_a = User("손흥민")
user_b = User("이강인")

user_a.show()
user_b.show()
```

**실행 결과**

```text
손흥민
이강인
```

| 개념 | 의미 | 예시 |
|---|---|---|
| 클래스 | 객체의 설계도 | `User` |
| 인스턴스 | 클래스로 만든 객체 | `user_a` |
| 생성자 초기화 메서드 | 객체 생성 시 초기화 | `__init__()` |
| 인스턴스 변수 | 객체마다 저장되는 값 | `self.name` |
| 메서드 | 클래스 내부에 정의된 함수 | `show()` |

### 2-2. `self`의 의미

```python
def __init__(self, name):
    self.name = name
```

- `self`: 현재 생성되는 객체 자신
- `name`: 외부에서 전달받은 인수
- `self.name`: 해당 객체에 저장되는 인스턴스 변수

`User("손흥민")`을 호출하면 전달된 이름이 해당 인스턴스의 `name` 속성에 저장된다.

### 2-3. `type()`, `id()`, `is`

```python
print(type(user_a))
print(id(user_a))
print(user_a is user_b)
```

- `type()`: 객체의 자료형 확인
- `id()`: 객체의 식별값 확인
- `is`: 두 변수가 같은 객체를 가리키는지 확인

`user_a`와 `user_b`는 같은 클래스로 만들었지만 서로 다른 인스턴스다.

## 3. 클래스 실습

### 3-1. Monitor 클래스

모니터의 해상도와 크기를 속성으로 저장하는 실습을 진행했다.

학습 중 사용한 속성 예시:

```python
self.resoultion = "1920*1080"
self.size = "27인치"
```

**수정 사항:** `resoultion`은 오타이며, `resolution`이 올바른 표기다. 해상도 표현도 일반적으로 `"1920x1080"`을 사용한다.

### 3-2. SmartPhone 클래스

스마트폰의 모델명과 배터리 잔량을 관리했다.

```python
class SmartPhone:
    def __init__(self, model):
        self.model = model
        self.battery = 50

    def charge(self, amount):
        self.battery = min(100, self.battery + amount)
```

핵심은 서로 다른 스마트폰 인스턴스가 각자의 배터리 값을 가진다는 점이다.

`min(100, ...)`을 사용하면 충전량이 100을 초과하지 않도록 제한할 수 있다.

### 3-3. BankAccount 클래스

은행 계좌를 객체로 표현하고 입금·출금 기능을 구현했다.

주요 속성과 메서드:

- `owner`: 계좌 소유자
- `balance`: 잔액
- `deposit(amount)`: 입금
- `withdraw(amount)`: 출금
- `__str__()`: 사람이 읽기 좋은 문자열 표현
- `__repr__()`: 객체의 개발자용 표현

출금할 때는 잔액이 충분한지 먼저 확인해야 한다.

```python
if amount > self.balance:
    print("잔액이 부족합니다.")
    return 0
```

**개선할 점:** 입금액이나 출금액이 0 이하인 경우도 검증하면 더 안전하다.

## 4. 쇼핑카트 프로그램 구현

### 4-1. 과제 요구사항

1. `Product` 클래스 생성
2. 상품명과 가격을 속성으로 저장
3. `ShoppingCart` 클래스 생성
4. 상품 추가·삭제·조회 메서드 작성
5. 상품 3개 생성
6. 장바구니에 2개 담고 1개 제거
7. 남은 상품 출력

### 4-2. 최종 작성 코드

```python
# 장바구니 클래스
class ShoppingCart:
    def __init__(self):
        self.items = []

    # 장바구니 담기
    def add_item(self, product):
        self.items.append(product)

    # 장바구니 빼기
    def remove_item(self, product):
        self.items.remove(product)

    # 상품 목록 조회
    def show_items(self):
        return self.items


# 상품 클래스
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price


# 장바구니 생성
cart = ShoppingCart()

# 상품 3개 생성
product_a = Product("사과", 3000)
product_b = Product("바나나", 2000)
product_c = Product("딸기", 5000)

# 상품 2개 추가
cart.add_item(product_a)
cart.add_item(product_b)

# 상품 1개 제거
cart.remove_item(product_b)

# 상품 목록 출력
for product in cart.show_items():
    print(product.name, product.price)
```

**실행 결과**

```text
사과 3000
```

### 4-3. 클래스별 역할

| 구분 | Product | ShoppingCart |
|---|---|---|
| 역할 | 상품 정보 관리 | 상품 목록 관리 |
| 속성 | `name`, `price` | `items` |
| 메서드 | 초기화 메서드 | 추가·삭제·조회 |
| 인스턴스 | `product_a` | `cart` |

### 4-4. 객체를 리스트에 저장하기

```python
cart.add_item(product_a)
```

이때 `product_a`는 단순 문자열이 아니라 `Product` 클래스로 생성한 객체다.

```python
def add_item(self, product):
    self.items.append(product)
```

따라서 장바구니에는 상품 객체가 저장되고, 다음처럼 각 상품의 속성에 접근할 수 있다.

```python
for product in cart.show_items():
    print(product.name, product.price)
```

### 4-5. 실습 중 헷갈렸던 부분

| 처음 작성한 코드 | 문제점 | 수정 |
|---|---|---|
| `def __inti__()` | 초기화 메서드 오타 | `__init__()` |
| `def add.item()` | 함수 이름에 점 사용 | `add_item()` |
| `self = product` | 객체 속성을 저장하지 않음 | `self.name = name` |
| `return append(self)` | 리스트 메서드 사용법 오류 | `self.items.append(product)` |
| `return self, product` | 상품 목록을 반환하지 않음 | `return self.items` |
| 없는 상품 제거 | `ValueError` 발생 | 담긴 상품 제거 |
| `show_items(product_b)` | 불필요한 인수 전달 | `show_items()` |

**추가 개선:** `remove_item()`에서 상품이 목록에 존재하는지 `if product in self.items:`로 검사하면 없는 상품을 제거할 때 발생하는 오류를 예방할 수 있다.

## 5. VS Code 디버깅

디버깅은 프로그램을 한 줄씩 실행하면서 변수의 상태와 코드의 실행 흐름을 확인하는 과정이다.

## 6. 오후 — 가위바위보 게임 구현

어제는 게임의 요구사항을 정리했고, 오늘은 실제 코드로 옮기는 작업을 진행했다.

### 6-1. 컴퓨터의 선택 생성

```python
import random

choices = {
    1: "가위",
    2: "바위",
    3: "보"
}

computer_number = random.randint(1, 3)
computer_choice = choices[computer_number]
```

`random.randint(1, 3)`은 1부터 3까지의 정수 중 하나를 무작위로 생성한다.

딕셔너리를 이용해 숫자를 가위·바위·보 문자열로 변환한다.

### 6-2. 반복 실행과 종료

```python
while True:
    user_input = input("가위(1), 바위(2), 보(3), 종료(q): ")

    if user_input == "q":
        break
```

- `while True`: 게임 반복
- `input()`: 사용자 입력
- `break`: 반복문 종료

### 6-3. 사용자 입력값 검증

```python
if not user_input.isdecimal():
    print("숫자를 입력해주세요.")
    continue

user_number = int(user_input)

if user_number not in (1, 2, 3):
    print("1~3 사이의 숫자를 입력해주세요.")
    continue

user_choice = choices[user_number]
```

입력 검증은 다음 순서로 진행한다.

1. 종료 명령인지 확인
2. 숫자 형태인지 확인
3. 정수로 변환
4. 허용 범위인 1~3인지 확인
5. 딕셔너리에서 선택값 조회

**주의:** `input()`의 반환값은 문자열이므로 `int()`로 변환해야 숫자로 비교할 수 있다.

### 6-4. 승패 판정

```python
if user_choice == computer_choice:
    print("무승부!")

elif (
    (user_choice == "가위" and computer_choice == "보")
    or (user_choice == "바위" and computer_choice == "가위")
    or (user_choice == "보" and computer_choice == "바위")
):
    print("승리!")

else:
    print("패배!")
```

가위바위보는 단순한 숫자 크기 비교로 승패를 결정할 수 없다.

| 사용자 | 컴퓨터 | 결과 |
|---|---|---|
| 가위 | 보 | 승리 |
| 바위 | 가위 | 승리 |
| 보 | 바위 | 승리 |
| 같은 선택 | 같은 선택 | 무승부 |
| 나머지 경우 | | 패배 |

오늘 확인된 구현 범위는 **무작위 선택, 입력 검증, 종료, 무승부·승리·패배 판정까지**다.

점수 누적, 사용자 이름, 3판 2선승, 전적 저장, 연승 기능은 추가 구현 과제로 남겨둔다.

## 8. 오늘의 실수와 배운 점

### 실수 1. 클래스의 역할을 구분하지 못함

처음에는 장바구니 클래스에 상품명과 가격을 저장하려 했다.

**배운 점:** 각 클래스가 어떤 데이터를 관리하고 어떤 일을 수행하는지 먼저 정해야 한다.

### 실수 2. `self`와 매개변수를 혼동함

`append(self)`처럼 작성했지만, 추가해야 하는 것은 장바구니 객체가 아니라 전달받은 상품 객체였다.

**배운 점:** `self`는 메서드를 호출한 객체이고, `product`는 메서드에 전달된 상품이다.

### 실수 3. 메서드의 반환값과 출력의 차이를 혼동함

`show_items()`는 리스트를 반환하고, 실제 출력은 `for`문에서 수행한다.

**배운 점:** `return`과 `print()`는 역할이 다르다.

### 실수 4. 가위바위보의 승리 조건 작성

숫자 크기 비교가 아니라 가위·바위·보의 상성을 조건식으로 표현해야 했다.

**배운 점:** 복잡한 조건은 먼저 가능한 경우를 표로 정리하면 구현하기 쉽다.
