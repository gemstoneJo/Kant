## 2. 데이터베이스와 PostgreSQL의 이해

### 2.1 SQL이란?

SQL(Structured Query Language)은 관계형 데이터베이스에서 데이터를 생성, 조회, 수정, 삭제할 때 사용하는 언어다.

| 명령어 | 의미 | 기능 |
|---|---|---|
| `CREATE DATABASE` | 생성 | 데이터베이스 생성 |
| `CREATE TABLE` | 생성 | 테이블 생성 |
| `INSERT INTO` | 삽입 | 새로운 데이터 입력 |
| `SELECT` | 조회 | 저장된 데이터 확인 |
| `UPDATE` | 수정 | 기존 데이터 수정 |
| `DELETE FROM` | 삭제 | 특정 데이터 삭제 |
| `DROP TABLE` | 삭제 | 테이블 자체 삭제 |
| `ALTER TABLE` | 변경 | 테이블 구조 변경 |

### 2.2 PostgreSQL이란?

PostgreSQL은 SQL을 사용하여 데이터를 관리하는 관계형 데이터베이스 관리 시스템(RDBMS)이다.

- SQL: 데이터베이스에 명령을 내리는 언어
- PostgreSQL: SQL 명령을 실행하고 데이터를 관리하는 소프트웨어
- Docker: PostgreSQL을 격리된 컨테이너 환경에서 실행하는 도구
- psql: PostgreSQL에 명령을 입력하기 위한 터미널 프로그램

### 2.3 전체 작동 구조

```text
사용자
  ↓ SQL 명령어 입력
VS Code 터미널 / DBCode
  ↓
PostgreSQL 서버
  ↓
product_shop 데이터베이스
  ↓
테이블
  ├── product
  ├── category
  └── shopping_cart
  ↓
데이터 저장 및 조회
```

Docker는 PostgreSQL 서버를 실행하는 환경이고, SQL은 PostgreSQL 내부 데이터를 관리하기 위한 언어다.

## 3. Docker Compose로 PostgreSQL 실행

### 3.1 docker-compose.yaml

오늘 생활체육 회원관리 실습에 사용한 설정이다.

```yaml
name: sportscenter

services:
  db:
    container_name: sportscenter-db
    image: postgres:18
    environment:
      POSTGRES_PASSWORD: postgres
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql

volumes:
  pgdata:
```

### 3.2 주요 설정 설명

| 설정 | 역할 |
|---|---|
| `name` | Docker Compose 프로젝트 이름 |
| `services` | 실행할 서비스 목록 |
| `db` | PostgreSQL 서비스 이름 |
| `container_name` | 컨테이너 이름 |
| `image` | 사용할 PostgreSQL 이미지 |
| `environment` | 환경변수 설정 |
| `POSTGRES_PASSWORD` | 최초 초기화할 관리자 비밀번호 |
| `ports` | 호스트와 컨테이너 포트 연결 |
| `volumes` | 데이터 저장 공간 연결 |

`5432:5432`에서 앞쪽은 내 컴퓨터의 포트, 뒤쪽은 컨테이너의 포트다.

`volumes`를 사용하면 컨테이너를 삭제하고 다시 만들더라도 볼륨이 유지되는 한 기존 데이터가 남을 수 있다.

### 3.3 Docker 명령어

| 명령어 | 기능 |
|---|---|
| `docker --version` | Docker 버전 확인 |
| `docker compose version` | Docker Compose 버전 확인 |
| `docker compose up -d` | 컨테이너를 백그라운드로 생성 및 실행 |
| `docker compose ps` | 컨테이너 상태 확인 |
| `docker volume ls` | Docker 볼륨 목록 확인 |
| `docker compose stop` | 컨테이너 중지 |
| `docker compose start` | 중지된 컨테이너 실행 |
| `docker compose exec db psql -U postgres` | 실행 중인 DB 컨테이너에서 PostgreSQL 접속 |

실습에서는 다음 명령어를 사용했다.

```bash
docker compose up -d
```

- `up`: Compose 서비스 생성 및 실행
- `-d`: 백그라운드로 실행

이후 데이터베이스에 접속했다.

```bash
docker compose exec db psql -U postgres
```

- `exec`: 실행 중인 컨테이너 내부에서 명령어 실행
- `db`: Compose 서비스 이름
- `psql`: PostgreSQL 명령어 프로그램
- `-U postgres`: postgres 사용자로 접속

### 3.4 DBCode 연결 오류

**발생한 오류**

```text
password authentication failed for user "sportscenter"
```

**원인**

Docker 프로젝트 이름인 `sportscenter`를 PostgreSQL 사용자 이름으로 착각했다.

현재 Compose 설정에서 `POSTGRES_USER`를 지정하지 않았으므로 최초 초기화 시 기본 관리자 계정은 `postgres`가 된다.

**해결**

```text
Host: localhost
Port: 5432
Username: postgres
Password: postgres
```

데이터베이스를 생성한 다음에는 해당 데이터베이스 이름을 선택하여 접속한다.

**복습:** Docker 프로젝트 이름, 컨테이너 이름, PostgreSQL 사용자 이름, 데이터베이스 이름은 서로 다른 개념이다.

## 4. 데이터베이스 생성과 접속

### 4.1 PostgreSQL 접속

```bash
docker compose exec db psql -U postgres
```

접속 성공 시:

```text
postgres=#
```

### 4.2 PostgreSQL 버전 확인

```sql
SELECT version();
```

현재 실행 중인 PostgreSQL 버전을 확인한다.

### 4.3 데이터베이스 생성

```sql
CREATE DATABASE sportscenter;
```

`CREATE DATABASE`는 새로운 데이터베이스를 생성하는 명령어다.

### 4.4 데이터베이스 목록 확인

```text
\l
```

PostgreSQL에 존재하는 데이터베이스 목록을 보여준다.

### 4.5 데이터베이스 이동

```text
\c sportscenter
```

접속 성공 시:

```text
sportscenter=#
```

`postgres=#`에서 `sportscenter=#`로 바뀌었다면 현재 접속 중인 데이터베이스가 변경된 것이다.

### 4.6 데이터베이스에 바로 접속하기

```bash
docker compose exec db psql -U postgres -d sportscenter
```

- `-U`: 사용자 지정
- `-d`: 데이터베이스 지정

### 4.7 psql 주요 명령어

| 명령어 | 의미 |
|---|---|
| `\l` | 데이터베이스 목록 |
| `\c 데이터베이스명` | 데이터베이스 이동 |
| `\dt` | 테이블 목록 |
| `\d 테이블명` | 테이블 구조 확인 |
| `\q` | PostgreSQL 종료 |
| `\r` | 작성 중인 SQL 입력 초기화 |
| `Ctrl + C` | 현재 입력 취소 |
| `q` | 조회 결과의 pager 화면 종료 |

**주의:** `\l`, `\dt`, `\c` 같은 명령어는 일반 SQL이 아닌 psql 전용 명령어다.

## 5. 테이블 생성 — CREATE TABLE

### 5.1 기본 문법

```sql
CREATE TABLE 테이블명
(
    컬럼명 자료형 제약조건,
    컬럼명 자료형 제약조건
);
```

테이블은 행(Row)과 열(Column)로 구성된다.

- 행: 개별 데이터 한 건
- 열: 데이터의 속성
- 자료형: 어떤 종류의 값을 저장할지 지정
- 제약조건: 데이터 입력 시 지켜야 하는 규칙

### 5.2 오늘 사용한 자료형

| 자료형 | 설명 | 사용 예 |
|---|---|---|
| `INT` | 정수 | 가격, 수량 |
| `SMALLINT` | 범위가 작은 정수 | 출생연도, 정원 |
| `SERIAL` | 자동 증가 정수 번호 | 회원 ID |
| `VARCHAR(30)` | 최대 30글자 문자열 | 이름 |
| `CHAR(1)` | 고정 길이 1글자 문자열 | 성별 |
| `DATE` | 날짜 | 가입일 |
| `TIME` | 시간 | 수업 시작 시간 |

`VARCHAR(30)`은 최대 30글자를 저장할 수 있으며, 정확하게 30글자를 입력해야 한다는 뜻은 아니다.

### 5.3 회원 테이블 생성

```sql
CREATE TABLE members
(
    member_id   SERIAL PRIMARY KEY,
    name        VARCHAR(30) NOT NULL,
    gender      CHAR(1) NOT NULL,
    birth_year  SMALLINT NOT NULL,
    phone       VARCHAR(20),
    email       VARCHAR(50),
    region      VARCHAR(10),
    join_date   DATE NOT NULL
);
```

`members` 테이블의 주요 정보:

- `member_id`: 회원을 구분하는 고유번호
- `name`: 회원 이름
- `gender`: 성별
- `birth_year`: 출생연도
- `phone`: 전화번호
- `email`: 이메일
- `region`: 거주 지역
- `join_date`: 가입일

### 5.4 테이블 구조 확인

```text
\dt
\d members
```

- `\dt`: 생성된 테이블 목록
- `\d members`: members 테이블의 자료형과 제약조건 확인

## 6. PRIMARY KEY와 SERIAL

### 6.1 PRIMARY KEY란?

`PRIMARY KEY`는 기본키로, 테이블에서 각 행을 구분하는 고유한 값이다.

특징:

- 중복 불가능
- NULL 불가능
- 테이블의 데이터를 구분하는 식별자

```sql
member_id SERIAL PRIMARY KEY
```

### 6.2 INT와 SERIAL의 차이

| 구분 | INT PRIMARY KEY | SERIAL PRIMARY KEY |
|---|---|---|
| 저장 값 | 정수 | 정수 |
| 자동 번호 생성 | 기본적으로 없음 | 있음 |
| 번호 직접 지정 | 일반적으로 필요 | 생략 가능 |
| 중복 허용 | 불가능 | 불가능 |
| 대표 사용 사례 | 실제 사물함 번호 | 회원 ID, 상품 ID |

**INT 사용 사례**

```sql
locker_no INT PRIMARY KEY
```

실제 사물함 번호가 101번, 102번처럼 정해져 있으므로 직접 입력한다.

**SERIAL 사용 사례**

```sql
product_id SERIAL PRIMARY KEY
```

새 상품이 등록될 때 고유번호를 자동 생성할 수 있다.

`SERIAL`은 내부적으로 정수 컬럼과 자동 번호 생성을 위한 시퀀스를 설정하는 방식이다. 따라서 번호가 반드시 빠짐없이 연속되는 것은 아니다.

## 7. INSERT INTO — 데이터 입력

### 7.1 기본 문법

```sql
INSERT INTO 테이블명 (컬럼1, 컬럼2)
VALUES (값1, 값2);
```

`INSERT INTO`는 테이블에 새로운 행을 추가하는 명령어다.

### 7.2 회원 데이터 추가

```sql
INSERT INTO members
(name, gender, birth_year, phone, email, region, join_date)
VALUES
('김하늘', 'F', 1995, '010-1234-5678',
 'haneul@example.com', '마포구', '2026-09-01');
```

`member_id`를 생략했지만 `SERIAL`이므로 자동으로 번호가 생성된다.

### 7.3 NULL 사용

```sql
INSERT INTO members
(name, gender, birth_year, phone, email, region, join_date)
VALUES
('이준호', 'M', 1988, '010-2345-6789',
 NULL, '서대문구', '2026-09-03');
```

`NULL`은 값이 존재하지 않거나 알려지지 않았다는 의미다.

문자열 `'NULL'`과 실제 `NULL`은 다르다.

`NOT NULL` 제약조건이 없는 컬럼에는 NULL을 저장할 수 있다.

### 7.4 데이터 입력 시 주의사항

- 컬럼 개수와 값의 개수가 일치해야 한다.
- 컬럼 순서와 값의 순서가 일치해야 한다.
- 문자열은 작은따옴표로 감싼다.
- 컬럼 사이에는 쉼표를 작성한다.
- 명령어 마지막에는 세미콜론을 작성한다.

## 8. SELECT — 데이터 조회

### 8.1 전체 데이터 조회

```sql
SELECT * FROM members;
```

- `SELECT`: 데이터를 조회
- `*`: 모든 컬럼
- `FROM`: 조회할 테이블 지정

### 8.2 원하는 컬럼만 조회

```sql
SELECT name, region FROM members;
```

회원 이름과 지역만 조회한다.

```sql
SELECT name, join_date FROM members;
```

회원 이름과 가입일만 조회한다.

### 8.3 조건에 맞는 데이터 조회

```sql
SELECT *
FROM members
WHERE member_id = 1;
```

`WHERE`는 원하는 조건에 해당하는 데이터만 조회할 때 사용한다.

## 9. FOREIGN KEY — 외래키

### 9.1 외래키란?

외래키(FK)는 다른 테이블의 기본키 또는 UNIQUE 키를 참조하여 테이블 간 관계를 만드는 제약조건이다.

```sql
sports_id INT NOT NULL REFERENCES sports(sports_id)
```

이 코드는 `sports` 테이블에 실제로 존재하는 종목 ID만 사용할 수 있게 한다.

### 9.2 종목 테이블

```sql
CREATE TABLE sports
(
    sports_id   SERIAL PRIMARY KEY,
    sports_name VARCHAR(20) NOT NULL
);
```

데이터 입력:

```sql
INSERT INTO sports (sports_name) VALUES ('수영');
INSERT INTO sports (sports_name) VALUES ('헬스');
```

예상 데이터:

| sports_id | sports_name |
|---|---|
| 1 | 수영 |
| 2 | 헬스 |

### 9.3 강좌 테이블

```sql
CREATE TABLE courses
(
    course_id   SERIAL PRIMARY KEY,
    sports_id   INT NOT NULL REFERENCES sports(sports_id),
    course_name VARCHAR(30) NOT NULL,
    level       VARCHAR(10) NOT NULL,
    class_days  VARCHAR(10) NOT NULL,
    start_time  TIME NOT NULL,
    capacity    SMALLINT NOT NULL,
    fee         INT NOT NULL
);
```

### 9.4 강좌 데이터 입력

```sql
INSERT INTO courses
(sports_id, course_name, level, class_days, start_time, capacity, fee)
VALUES
(1, '수영 초급 새벽반', '초급', '월수금', '06:00', 20, 70000);
```

### 9.5 존재하지 않는 외래키 입력

```sql
INSERT INTO courses
(sports_id, course_name, level, class_days, start_time, capacity, fee)
VALUES
(30, '헬스 자유이용', '자유', '매일', '06:00', 50, 50000);
```

**발생한 오류**

```text
violates foreign key constraint
Key (sports_id)=(30) is not present in table "sports".
```

원인:

`sports` 테이블에 `sports_id = 30`이 존재하지 않는다.

따라서 PostgreSQL이 존재하지 않는 종목의 강좌가 생성되는 것을 막는다.

### 9.6 외래키로 참조 중인 데이터 삭제

```sql
DELETE FROM sports WHERE sports_id = 1;
```

1번 종목을 참조하는 강좌가 존재하면, 기본 외래키 동작에 따라 삭제가 거부된다.

**핵심:** 외래키는 테이블 간 관계를 설정하고 잘못된 참조를 막아 데이터 무결성을 유지한다.

## 10. UNIQUE — 중복 데이터 방지

### 10.1 UNIQUE란?

`UNIQUE`는 특정 컬럼에서 동일한 값이 중복되지 않도록 제한하는 제약조건이다.

오늘 사물함 테이블에서는 다음과 같이 사용했다.

```sql
member_id INT NOT NULL UNIQUE REFERENCES members(member_id)
```

### 10.2 사물함에 UNIQUE가 필요한 이유

회원 한 명에게 사물함을 최대 하나만 배정하기 위해서다.

예를 들어:

```sql
INSERT INTO lockers VALUES (101, 1, '2026-11-16');
```

회원 1번에게 101번 사물함을 배정한다.

이후 같은 회원에게 다른 사물함을 배정하면:

```sql
INSERT INTO lockers VALUES (201, 1, '2026-11-16');
```

중복 오류가 발생한다.

```text
duplicate key value violates unique constraint
```

`locker_no`의 PRIMARY KEY는 사물함 번호 중복을 막는다.

`member_id`의 UNIQUE는 같은 회원이 여러 사물함을 배정받는 것을 막는다.

### 10.3 PRIMARY KEY와 UNIQUE 비교

| 구분 | PRIMARY KEY | UNIQUE |
|---|---|---|
| 중복값 | 불가능 | 불가능 |
| NULL | 불가능 | 기본적으로 허용 |
| 역할 | 행의 고유 식별 | 특정 값의 중복 방지 |

`UNIQUE`와 `NOT NULL`을 함께 사용하면 중복도 불가능하고 NULL도 불가능하다.

## 11. ON DELETE CASCADE — 연쇄 삭제

### 11.1 사물함 테이블

```sql
CREATE TABLE lockers
(
    locker_no  INT PRIMARY KEY,
    member_id  INT NOT NULL UNIQUE
               REFERENCES members(member_id)
               ON DELETE CASCADE,
    asign_date DATE NOT NULL
);
```

### 11.2 ON DELETE CASCADE란?

참조하고 있는 부모 테이블의 데이터가 삭제되면, 해당 데이터를 참조하는 자식 테이블의 행도 자동 삭제되도록 하는 설정이다.

### 11.3 수업 실습 과정

임시회원 추가:

```sql
INSERT INTO members
(name, gender, birth_year, join_date)
VALUES
('임시회원', 'M', 2000, '2026-11-01');
```

사물함 배정:

```sql
INSERT INTO lockers
VALUES (102, 3, '2026-11-16');
```

회원 삭제:

```sql
DELETE FROM members
WHERE member_id = 3;
```

결과:

- members에서 3번 회원 삭제
- lockers에서 3번 회원에게 배정된 사물함 행도 자동 삭제

### 11.4 주의사항

`ON DELETE CASCADE`는 편리하지만, 실제 서비스에서는 관련 데이터가 의도치 않게 삭제될 수 있으므로 주의해서 사용해야 한다.

## 12. 데이터 무결성과 CHECK 제약조건

### 12.1 데이터 무결성이란?

데이터베이스에 저장되는 데이터가 정확하고 일관된 상태를 유지하는 것을 의미한다.

예를 들어:

- 상품 가격이 음수면 안 된다.
- 상품 재고가 음수면 안 된다.
- 같은 회원이 사물함을 중복 배정받으면 안 된다.
- 존재하지 않는 상품을 장바구니에 담으면 안 된다.

이런 규칙을 제약조건으로 설정할 수 있다.

### 12.2 CHECK

```sql
price INT NOT NULL CHECK (price >= 0)
```

가격은 반드시 입력되어야 하며, 0 이상이어야 한다.

```sql
qty INT NOT NULL CHECK (qty >= 0)
```

상품 재고는 0개가 가능하지만 음수는 불가능하다.

```sql
qty INT NOT NULL CHECK (qty > 0)
```

장바구니 수량은 최소 1개 이상이어야 한다.

### 12.3 주요 제약조건 비교

| 제약조건 | 기능 |
|---|---|
| `PRIMARY KEY` | 고유한 행 식별 |
| `NOT NULL` | NULL 입력 방지 |
| `UNIQUE` | 중복값 방지 |
| `CHECK` | 지정된 조건 검사 |
| `REFERENCES` | 외래키 관계 설정 |
| `ON DELETE CASCADE` | 참조 대상 삭제 시 연관 행 자동 삭제 |

## 13. DROP TABLE과 ALTER TABLE

### 13.1 DROP TABLE

기존 테이블 자체를 삭제한다.

```sql
DROP TABLE lockers;
```

테이블과 그 안의 데이터가 삭제된다.

테이블이 존재할 때만 삭제하려면:

```sql
DROP TABLE IF EXISTS lockers;
```

`IF EXISTS`를 사용하면 테이블이 없어도 오류 대신 알림이 출력된다.

### 13.2 ALTER TABLE

기존 테이블의 구조를 변경한다.

```sql
ALTER TABLE lockers
ADD COLUMN user_name VARCHAR(30);
```

컬럼을 추가하는 명령어다.

컬럼 이름을 변경할 수도 있다.

```sql
ALTER TABLE lockers
RENAME COLUMN asign_date TO assign_date;
```

### 13.3 차이점

| 구분 | DROP TABLE | ALTER TABLE |
|---|---|---|
| 목적 | 테이블 삭제 | 테이블 구조 변경 |
| 기존 데이터 | 삭제됨 | 변경 종류에 따라 유지 가능 |
| 활용 | 실습 초기화 | 컬럼 추가, 이름 변경 등 |

오늘 튜터님은 학습 단계에서 테이블 구조를 잘못 만들었다면 삭제하고 다시 생성하는 방법을 권장하셨다.

실습 데이터가 필요 없는 환경에서는 이해하기 쉬운 방법이다.

하지만 실제 운영 중인 데이터베이스에서는 데이터 보존, 제약조건, 잠금 등을 고려하여 구조를 안전하게 변경해야 한다.

## 14. JOIN과 AS — 추가로 이해한 개념

이 부분은 오늘 직접 질문하면서 추가로 알아본 내용이다.

### 14.1 JOIN이란?

서로 다른 테이블을 공통된 값을 기준으로 연결해 조회하는 방법이다.

예를 들어 사물함 정보와 회원 이름을 함께 조회할 수 있다.

```sql
SELECT *
FROM lockers
JOIN members
ON lockers.member_id = members.member_id;
```

- `FROM lockers`: 사물함 테이블에서 시작
- `JOIN members`: 회원 테이블 연결
- `ON`: 연결 조건 지정
- `lockers.member_id = members.member_id`: 회원 ID가 같은 행 연결

### 14.2 AS란?

`AS`는 테이블이나 조회 결과 컬럼에 별명을 붙이는 명령어다.

```sql
FROM lockers AS l
JOIN members AS m
```

- `l`: lockers의 별명
- `m`: members의 별명

따라서:

```sql
l.locker_no
m.name
```

각각 사물함 번호와 회원 이름을 의미한다.

### 14.3 컬럼 이름에 별명 붙이기

```sql
SELECT m.name AS user_name
```

실제 컬럼 이름은 `name`이지만, 조회 결과에서는 `user_name`이라고 표시한다.

원본 테이블의 컬럼 이름이 변경되는 것은 아니다.

### 14.4 JOIN 전체 예시

```sql
SELECT
    l.locker_no,
    l.member_id,
    m.name AS user_name,
    l.asign_date
FROM lockers AS l
JOIN members AS m
    ON l.member_id = m.member_id;
```

**중요:** JOIN은 두 테이블을 연결해서 조회하는 것이지, 테이블 자체를 합치거나 수정하는 것이 아니다.

## 15. SQL 실습 과제 01 — 상품 데이터베이스 설계

### 15.1 과제 목표

상품 관리용 데이터베이스를 직접 설계하고 생성한다.

생성할 테이블:

1. `product`: 상품 정보
2. `category`: 상품 카테고리
3. `shopping_cart`: 사용자 장바구니

### 15.2 데이터베이스 생성

```sql
CREATE DATABASE product_shop;
```

psql에서 데이터베이스 이동:

```text
\c product_shop
```

### 15.3 최종 실습 설계

아래는 직접 작성한 설계를 바탕으로 상품명, 카테고리명, 장바구니 수량의 제약조건을 보완한 코드다.

```sql
-- 상품 테이블
CREATE TABLE product
(
    product_id   SERIAL PRIMARY KEY,
    product_name VARCHAR(30) NOT NULL,
    price        INT NOT NULL CHECK (price >= 0),
    qty          INT NOT NULL CHECK (qty >= 0),
    category     VARCHAR(30),
    description  VARCHAR(255)
);

-- 카테고리 테이블
CREATE TABLE category
(
    category_id   SERIAL PRIMARY KEY,
    category_name VARCHAR(30) NOT NULL UNIQUE,
    description   VARCHAR(255)
);

-- 장바구니 테이블
CREATE TABLE shopping_cart
(
    cart_id    SERIAL PRIMARY KEY,
    user_id    INT NOT NULL,
    product_id INT NOT NULL REFERENCES product(product_id),
    qty        INT NOT NULL CHECK (qty > 0)
);
```

**참고:** 실제 터미널에서 최종 확인한 최초 생성 구조에서는 `product_name`, `category_name`, `shopping_cart.qty`의 일부 제약조건이 적용되지 않은 상태였다. 위 코드는 보완한 설계이므로, 수정 후 재생성했다면 `\d`로 실제 적용 상태를 다시 확인해야 한다.

### 15.4 설계 의도

**product**

- 상품 ID는 자동 발급
- 상품 가격은 0 이상
- 재고는 0 이상
- 상품명과 상품 설명 저장

**category**

- 카테고리 ID는 자동 발급
- 카테고리명은 필수
- 동일한 카테고리명 중복 방지

**shopping_cart**

- 장바구니 항목 ID는 자동 발급
- 사용자 ID 필수
- 존재하는 상품 ID만 참조 가능
- 장바구니 수량은 1 이상

### 15.5 테이블 간 관계

```text
product
  product_id (PK)
       ↑
       │ FOREIGN KEY
       │
shopping_cart
  product_id (FK)
```

상품과 장바구니는 외래키로 연결되어 있다.

현재 설계에서는 `product.category`가 문자열이므로 `category` 테이블과 직접 연결되지는 않는다.

또한 사용자 테이블을 별도로 생성하지 않았으므로 `shopping_cart.user_id`는 일반 정수 컬럼이다.

과제에서 요구한 세 테이블을 생성하고, 장바구니와 상품 간 외래키 관계를 설정하는 실습을 수행했다.

### 15.6 실행 결과 확인

```text
\dt
```

실제 조회 결과:

```text
category
product
shopping_cart
(3 rows)
```

테이블 구조 확인:

```text
\d product
\d category
\d shopping_cart
```

확인한 항목:

- 세 테이블 생성 성공
- 상품 가격 CHECK 제약조건
- 상품 재고 CHECK 제약조건
- 각 테이블 PRIMARY KEY
- 장바구니의 상품 외래키

## 16. 오늘 발생한 오류와 해결 과정

### 16.1 컬럼 사이 쉼표 누락

잘못된 코드:

```sql
name VARCHAR(30) NOT NULL
gender CHAR(1) NOT NULL
```

수정:

```sql
name VARCHAR(30) NOT NULL,
gender CHAR(1) NOT NULL,
```

SQL에서는 컬럼 사이에 쉼표가 필요하다.

### 16.2 컬럼 이름 오타

잘못된 코드:

```sql
INSERT INTO sports (sprot_name)
VALUES ('수영');
```

수정:

```sql
INSERT INTO sports (sports_name)
VALUES ('수영');
```

테이블에 실제로 존재하는 컬럼 이름을 정확하게 사용해야 한다.

### 16.3 REFERENCES 앞의 쉼표

잘못된 코드:

```sql
sports_id INT NOT NULL, REFERENCES sports(sports_id),
```

수정:

```sql
sports_id INT NOT NULL REFERENCES sports(sports_id),
```

외래키 제약조건을 같은 컬럼 정의에 작성할 때는 중간에 쉼표를 넣지 않는다.

### 16.4 기본키 중복

```sql
INSERT INTO members
(member_id, name, gender, birth_year, join_date)
VALUES (1, '조원석', 'M', 1995, '2026-11-16');
```

이미 `member_id = 1`인 데이터가 존재했기 때문에 오류가 발생했다.

```text
duplicate key value violates unique constraint
```

**해결:** 이미 존재하는 ID를 사용하지 않거나, SERIAL의 자동 생성 기능을 활용한다.

### 16.5 이미 존재하는 테이블 재생성

```sql
CREATE TABLE sports (...);
```

이미 `sports` 테이블이 있으면:

```text
relation "sports" already exists
```

실습에서 기존 테이블을 삭제해도 되는 경우:

```sql
DROP TABLE IF EXISTS sports;
```

다만 외래키로 참조 중인 테이블은 삭제가 제한될 수 있다.

### 16.6 SQL 명령어 종료 누락

```text
sportscenter=# SELECT * FROM courses
sportscenter-#
```

세미콜론을 입력하지 않아서 명령어가 끝나지 않았다.

해결:

```text
Ctrl + C
```

그다음:

```sql
SELECT * FROM courses;
```

### 16.7 psql 입력 화면 구분

| 화면 | 의미 | 해결 |
|---|---|---|
| `sportscenter=#` | 새 명령어 입력 가능 | 정상 |
| `sportscenter-#` | SQL 입력이 계속되는 중 | `;` 또는 `Ctrl+C` |
| `sportscenter(#` | 괄호가 닫히지 않음 | 괄호 확인 |
| `(END)` | 조회 결과 pager 화면 | `q` |
| `syntax error` | SQL 문법 오류 | 오류 위치와 앞줄 확인 |

### 16.8 psql에서 history 사용

수업 중 다음 명령어를 입력했다.

```text
history
```

하지만 `psql` 내부에서는 일반 Bash의 `history` 명령어처럼 사용되지 않는다.

Git Bash에서 입력한 명령어 이력을 확인할 때는 `history`를 사용한다.

psql에서는 위쪽 방향키로 이전 명령어를 불러올 수 있다.

## 18. 중요 복습 항목

### ★ 1. PRIMARY KEY와 FOREIGN KEY

- PK: 자기 테이블의 행을 식별
- FK: 다른 테이블의 데이터를 참조
- FK는 존재하지 않는 참조값 입력을 막는다.

### ★ 2. SERIAL과 INT

- `INT`: 일반 정수
- `SERIAL`: 자동 증가 번호 생성에 사용할 수 있는 정수
- 실제 사물함 번호처럼 직접 정해야 하는 값은 INT가 자연스럽다.
- 회원 ID나 상품 ID처럼 자동 발급하는 번호는 SERIAL이 편리하다.

### ★ 3. UNIQUE

- 같은 값의 중복을 방지한다.
- 사물함에서 member_id에 사용한 이유는 한 회원이 여러 사물함을 배정받지 못하게 하기 위해서다.

### ★ 4. ON DELETE CASCADE

- 부모 데이터 삭제 시 참조하는 자식 행도 삭제한다.
- 데이터를 자동 정리할 수 있지만 연쇄 삭제를 주의해야 한다.

### ★ 5. SQL 쉼표와 세미콜론

- `,`: 컬럼이나 값 구분
- `;`: SQL 명령어 종료
- 에러가 표시된 줄뿐 아니라 바로 앞줄도 확인해야 한다.
