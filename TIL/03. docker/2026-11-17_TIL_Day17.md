## 2. 스포츠센터 데이터베이스 실습

### 2-1. instructors 테이블 생성

```sql
CREATE TABLE instructors
(
    instructor_id SERIAL PRIMARY KEY,
    name VARCHAR(20) NOT NULL,
    sport_id INT NOT NULL REFERENCES sports(sport_id),
    phone VARCHAR(20),
    hire_date DATE NOT NULL
);
```

| 컬럼 | 자료형 | 역할 |
|---|---|---|
| `instructor_id` | SERIAL | 강사 고유 번호, 자동 증가 |
| `name` | VARCHAR(20) | 강사 이름, 필수 |
| `sport_id` | INT | 담당 종목 번호 |
| `phone` | VARCHAR(20) | 전화번호, 선택 |
| `hire_date` | DATE | 채용일, 필수 |

**학습 중 궁금했던 부분: `CHAR`와 `VARCHAR`**

전화번호를 `010-0000-0000` 형식으로 저장하려고 처음에는 `CHAR(12)`를 사용했다.

하지만 하이픈까지 포함하면 총 13자다.

- `CHAR(13)` : 고정 길이 13자
- `VARCHAR(20)` : 최대 20자까지 저장
- `CHAR(13)`만으로는 전화번호 형식 자체를 검증할 수 없다.

이번 과제에서는 최대 20자라는 조건을 고려하여 `VARCHAR(20)`을 사용했다.

### 2-2. 시드 데이터란?

시드 데이터(Seed Data)는 데이터베이스를 처음 구성할 때 넣는 초기 데이터다.

예를 들어 스포츠센터에서는 종목, 강사, 회원, 강좌, 사물함 및 수강 신청 정보를 미리 입력했다.

```sql
INSERT INTO sports (sport_name) VALUES
    ('수영'),
    ('헬스'),
    ('골프연습'),
    ('스포츠댄스');
```

실제 컬럼 이름이 `sport_name`인 테이블을 기준으로 한 예시다.

### 2-3. 스포츠센터 시드 데이터 오류

실행 명령어:

```sql
\i /tmp/sportscenter_sedd.sql
```

발생한 대표 오류:

```text
ERROR: column "sport_name" of relation "sports" does not exist
ERROR: column "sports_id" of relation "instructors" does not exist
```

**원인**

테이블을 만들 때 사용한 컬럼 이름과 시드 파일에 작성된 컬럼 이름이 달랐다.

| 실제 테이블 컬럼 | 시드 파일에서 사용한 이름 |
|---|---|
| `sports_name` | `sport_name` |
| `sport_id` | `sports_id` |

컬럼 이름이 일치해야 `INSERT INTO`가 정상적으로 실행된다.

### 2-4. 외래 키 오류의 연쇄 발생

```text
ERROR: insert or update on table "courses"
violates foreign key constraint
```

종목 데이터 입력이 실패하면서 해당 종목을 참조하는 강좌 데이터도 입력되지 않았다.

이후 강좌를 참조하는 수강 신청 데이터에서도 오류가 발생했다.

**핵심 개념**

외래 키로 연결된 데이터는 참조 대상이 먼저 존재해야 한다.

예시:

`종목 → 강좌 → 수강 신청`

단, 실제 테이블 설계에 따라 중간에 강사 등의 참조 관계가 추가될 수 있다.

### 2-5. SQL 파일 이름 및 경로 오류

```sql
\i /tmp/sportscenter_seed.sql
```

오류:

```text
No such file or directory
```

기존에 사용하던 파일 이름은 `sportscenter_sedd.sql`이었다.

`seed`와 `sedd`는 서로 다른 파일 이름이다.

파일 확인 명령어:

```sql
\! ls -l /tmp/*sportscenter*
```

컨테이너 내부 파일 확인:

```sql
\! sed -n '1,45p' /tmp/sportscenter_sedd.sql
```

**주의:** 로컬 컴퓨터에서 SQL 파일을 수정했다고 해서 이미 Docker 컨테이너에 복사해 둔 파일까지 자동으로 변경되는 것은 아니다.

## 3. Docker Compose로 상품 DB 생성

### 3-1. 새로운 환경을 만드는 이유

전날 만든 상품 데이터베이스와 오늘 과제용 데이터베이스를 분리하기 위해 새로운 Compose 환경을 구성했다.

| 실습 | 컨테이너 | 호스트 포트 |
|---|---|---|
| 스포츠센터 | sportscenter-db | 5432 |
| 전날 상품 과제 | product-db | 5433 |
| 오늘 상품 과제 | shop-db | 5434 |

PostgreSQL의 컨테이너 내부 포트는 모두 `5432`를 사용한다.

### 3-2. Docker Compose 설정

```yaml
name: shop

services:
  db:
    container_name: shop-db
    image: postgres:18
    environment:
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: shop
    ports:
      - "5434:5432"
    volumes:
      - shop_pgdata:/var/lib/postgresql

volumes:
  shop_pgdata:
```

**핵심 설정**

- `name` : Compose 프로젝트 이름
- `container_name` : Docker 컨테이너 이름
- `image` : 사용할 PostgreSQL 이미지
- `POSTGRES_PASSWORD` : 기본 사용자 비밀번호
- `POSTGRES_DB` : 최초 초기화 시 생성할 데이터베이스
- `ports` : 호스트와 컨테이너의 포트 연결
- `volumes` : 데이터를 영구적으로 저장하기 위한 볼륨

### 3-3. 포트 구조 이해

```yaml
ports:
  - "5434:5432"
```

- `5434` : 내 컴퓨터에서 접근할 포트
- `5432` : 컨테이너 내부 PostgreSQL 포트

서로 다른 컨테이너는 내부 포트가 같아도 문제가 없다.

다만 호스트에서 사용하는 포트는 충돌하지 않아야 한다.

### 3-4. Docker 볼륨 오류

발생한 오류:

```text
service "db" refers to undefined volume shop_pgdata
```

**원인**

서비스에서 사용하는 볼륨 이름과 최상위에서 선언한 볼륨 이름이 일치하지 않았다.

올바른 구조:

```yaml
services:
  db:
    volumes:
      - shop_pgdata:/var/lib/postgresql

volumes:
  shop_pgdata:
```

설정 확인:

```bash
docker compose config
```

컨테이너 실행:

```bash
docker compose up -d
```

실행 상태 확인:

```bash
docker ps
```

## 4. SQL의 DDL과 DML

### 4-1. DDL (Data Definition Language)

데이터베이스의 구조를 정의하는 명령어다.

| 명령어 | 기능 |
|---|---|
| `CREATE DATABASE` | 데이터베이스 생성 |
| `CREATE TABLE` | 테이블 생성 |
| `ALTER TABLE` | 기존 테이블 구조 변경 |
| `DROP TABLE` | 테이블 삭제 |
| `TRUNCATE TABLE` | 테이블의 전체 행 삭제 |

### 4-2. DML (Data Manipulation Language)

테이블에 저장된 데이터를 추가하거나 수정·삭제하는 명령어다.

| 명령어 | 기능 |
|---|---|
| `INSERT INTO` | 데이터 추가 |
| `UPDATE` | 데이터 수정 |
| `DELETE` | 데이터 삭제 |

참고로 `SELECT`는 데이터 조회에 사용하며, 분류 체계에 따라 DQL로 별도 구분하기도 한다.

### 4-3. INSERT INTO 다중 행 입력

처음에는 여러 데이터를 하나의 괄호에 넣거나 쉼표를 빠뜨리는 실수를 했다.

올바른 예시:

```sql
INSERT INTO category(category_name, description) VALUES
    ('전자제품', '전자제품 및 주변기기'),
    ('식품', '음식 및 음료'),
    ('생활용품', '일상생활에 필요한 상품');
```

**문법 규칙**

- 각 `()`는 한 개의 행(Row)을 나타낸다.
- 괄호 내부의 값은 컬럼 순서에 맞게 작성한다.
- 여러 행을 입력할 때는 행 사이에 쉼표를 사용한다.
- 마지막 행 뒤에는 세미콜론을 작성한다.

## 5. 상품 데이터베이스 실습

오늘 과제는 전날 작성한 상품 관련 테이블을 기반으로, 실제 시드 데이터를 작성하는 것이었다.

### 5-1. category 테이블

```sql
CREATE TABLE category
(
    category_id SERIAL PRIMARY KEY,
    category_name VARCHAR(30),
    description TEXT
);
```

```sql
INSERT INTO category(category_name, description) VALUES
    ('전자제품', '전자제품 및 주변기기'),
    ('식품', '음식 및 음료'),
    ('생활용품', '일상생활에 필요한 상품');
```

카테고리 3개를 입력하도록 구성했다.

### 5-2. product 테이블

```sql
CREATE TABLE product
(
    product_id SERIAL PRIMARY KEY,
    product_name VARCHAR(30),
    price INT NOT NULL CHECK (price >= 0),
    qty INT NOT NULL CHECK (qty >= 0),
    category INT NOT NULL REFERENCES category(category_id),
    description TEXT
);
```

**핵심 개념**

```sql
category INT NOT NULL REFERENCES category(category_id)
```

상품 테이블의 `category` 컬럼이 카테고리 테이블의 `category_id`를 참조한다.

처음에는 다음과 같이 작성했다.

```sql
category VARCHAR(30)
```

이 방식은 카테고리 이름을 직접 저장하지만, 다른 테이블의 카테고리와 관계를 강제하지 않는다.

외래 키를 사용하기 위해 정수형 컬럼으로 변경했다.

```sql
INSERT INTO product(product_name, price, qty, category, description) VALUES
    ('키보드', 49900, 50, 1, '기계식키보드'),
    ('마우스', 29900, 20, 1, '무선 마우스'),
    ('불닭볶음면', 4990, 100, 2, '불닭볶음면 4개입'),
    ('계란', 15990, 30, 2, '무항생제 유정란 20구'),
    ('샴푸', 4990, 20, 3, '엘라스틴 퍼퓸 460ml');
```

카테고리 ID가 1, 2, 3으로 생성되는 빈 데이터베이스를 가정한 예시다.

상품 데이터 5개를 입력하도록 구성했다.

### 5-3. member 테이블

```sql
CREATE TABLE member
(
    member_id SERIAL PRIMARY KEY,
    name VARCHAR(30) NOT NULL,
    gender CHAR(1) NOT NULL,
    birth_year SMALLINT NOT NULL,
    phone VARCHAR(20),
    email VARCHAR(50),
    region VARCHAR(10)
);
```

회원 데이터는 스포츠센터 실습 자료를 참고하여 총 60명분을 작성했다.

**발생했던 문법 오류**

```sql
region VARCHAR(10);
)
```

테이블 정의가 끝나기 전에 세미콜론을 작성했었다.

수정:

```sql
region VARCHAR(10)
);
```

### 5-4. shopping_cart 테이블

```sql
CREATE TABLE shopping_cart
(
    cart_id SERIAL PRIMARY KEY,
    user_id INT NOT NULL REFERENCES member(member_id),
    product_id INT NOT NULL REFERENCES product(product_id),
    qty INT NOT NULL CHECK (qty > 0)
);
```

이 테이블에는 두 개의 외래 키가 있다.

| 컬럼 | 참조 대상 |
|---|---|
| `user_id` | member(member_id) |
| `product_id` | product(product_id) |

시드 데이터:

```sql
INSERT INTO shopping_cart(user_id, product_id, qty) VALUES
    (1, 1, 1),
    (1, 2, 1),
    (2, 3, 1),
    (2, 4, 1),
    (2, 5, 1);
```

회원 1번은 상품 1번과 2번을 각각 하나씩 장바구니에 담았다.

회원 2번은 상품 3번, 4번, 5번을 각각 하나씩 담았다.

### 5-5. catalog 테이블

```sql
CREATE TABLE catalog
(
    catalog_id SERIAL PRIMARY KEY,
    catalog_name VARCHAR(30) NOT NULL,
    description TEXT
);
```

```sql
INSERT INTO catalog(catalog_name, description) VALUES
    ('베스트 상품', '인기 상품 모음'),
    ('할인 상품', '할인 진행중인 상품'),
    ('신상품', '처음 입고된 상품');
```

카탈로그 3개를 작성했다.

현재는 카탈로그와 상품을 연결하는 별도 관계 테이블이 없으므로 카탈로그 자체의 정보만 저장한다.

## 6. 데이터 무결성과 외래 키

### 6-1. PRIMARY KEY (PK)

테이블의 각 행을 유일하게 구별하는 기본 키다.

```sql
product_id SERIAL PRIMARY KEY
```

### 6-2. FOREIGN KEY (FK)

다른 테이블의 키를 참조하여 데이터 관계를 유지한다.

```sql
product_id INT NOT NULL REFERENCES product(product_id)
```

상품 테이블에 없는 상품 번호를 장바구니에 넣으면 외래 키 오류가 발생한다.

### 6-3. CHECK

데이터가 특정 조건을 만족하도록 제한한다.

상품 재고:

```sql
qty INT NOT NULL CHECK (qty >= 0)
```

장바구니 수량:

```sql
qty INT NOT NULL CHECK (qty > 0)
```

상품 재고는 품절 상태를 나타내기 위해 0이 가능하지만, 장바구니에 담는 수량은 1 이상이어야 한다는 설계를 적용했다.

### 6-4. 테이블 생성 순서

오늘 작성한 최종 파일의 생성 순서:

1. category
2. product
3. member
4. shopping_cart
5. catalog

`shopping_cart`는 회원과 상품 테이블을 참조하므로 두 테이블이 먼저 생성되어야 한다.

## 7. SQL 파일 실행 및 오류 해결

### 7-1. Git Bash와 PostgreSQL의 차이

| 화면 | 의미 | 사용하는 명령어 |
|---|---|---|
| `$` | Git Bash | docker, cd, ls |
| `shop=#` | PostgreSQL psql | SELECT, INSERT, CREATE TABLE |
| `shop-#` | SQL 문장 입력이 완료되지 않음 | 세미콜론 및 구문 확인 |

처음에는 `shop=#`에서 Docker 명령어를 입력하여 실행되지 않는 문제가 있었다.

PostgreSQL에서 나가기:

```sql
\q
```

입력 중인 명령 취소:

`Ctrl + C`

### 7-2. SQL 파일 실행

Git Bash에서:

```bash
docker exec -i shop-db psql -X -v ON_ERROR_STOP=1 -U postgres -d shop < shop_seed.sql
```

명령어 해석:

| 명령어 | 의미 |
|---|---|
| `docker exec` | 실행 중인 컨테이너에서 명령 실행 |
| `-i` | 표준 입력 유지 |
| `shop-db` | 컨테이너 이름 |
| `psql` | PostgreSQL 클라이언트 |
| `-X` | 사용자 시작 설정 파일을 읽지 않음 |
| `-v ON_ERROR_STOP=1` | SQL 오류 발생 시 실행 중단 |
| `-U postgres` | 접속 사용자 |
| `-d shop` | 접속 DB |
| `< shop_seed.sql` | 로컬 SQL 파일을 표준 입력으로 전달 |

### 7-3. 데이터베이스 중복 생성 오류

```text
ERROR: database "shop" already exists
```

**원인**

Compose에서 `POSTGRES_DB: shop`으로 데이터베이스를 생성했는데 SQL 파일에서도 다시 생성하려고 했다.

해결:

```sql
-- CREATE DATABASE shop;
```

이미 존재하는 DB를 사용할 때는 생성 구문을 제거한다.

### 7-4. 테이블 중복 생성 오류

```text
ERROR: relation "category" already exists
```

**원인**

기존에 생성된 `category` 테이블을 다시 생성하려고 했다.

테이블 확인:

```sql
\dt
```

실제 확인 결과:

```text
category
product
shopping_cart
```

세 개의 테이블이 이미 존재했으며, `member`, `catalog`는 목록에 없었다.

### 7-5. 테이블 삭제 후 다시 생성

실습 전용 데이터베이스에서 기존 데이터가 필요 없는 경우에 한해 사용할 수 있다.

```sql
DROP TABLE IF EXISTS shopping_cart;
DROP TABLE IF EXISTS product;
DROP TABLE IF EXISTS category;
```

외래 키를 참조하는 테이블을 먼저 삭제하는 것이 중요하다.

**주의:** `DROP TABLE`은 테이블 구조와 데이터가 모두 삭제되므로 실제 서비스 환경에서는 신중하게 사용해야 한다.

오늘 확인한 마지막 상태는 기존 테이블 3개가 존재한다는 것이며, 삭제 및 전체 시드 재적재의 성공 결과는 아직 확인하지 않았다.
