## 2. SELECT와 WHERE 조건 검색

### AND와 OR

```sql
SELECT course_name, level, start_time
FROM courses
WHERE sport_id = 1
AND (level = '초급' OR start_time < '09:00');
```

**설명**

종목 번호가 1번이면서 초급 강좌이거나 오전 9시 이전에 시작하는 강좌를 조회한다.

| 연산자 | 의미 |
|---|---|
| `AND` | 두 조건 모두 만족 |
| `OR` | 둘 중 하나 이상 만족 |
| `<>` | 같지 않음 |
| `>=` | 크거나 같음 |
| `<=` | 작거나 같음 |
| `BETWEEN A AND B` | A부터 B까지, 양 끝 포함 |
| `IS NULL` | 값이 NULL인지 확인 |
| `IS NOT NULL` | 값이 NULL이 아닌지 확인 |

### BETWEEN과 IS NULL 함께 사용하기

오후 1번 실습에서 활용한 문법이다.

```sql
SELECT member_id, name, birth_year, region, phone
FROM members
WHERE birth_year BETWEEN 1970 AND 1989
  AND email IS NULL
ORDER BY birth_year, member_id;
```

**배운 점**

`BETWEEN`과 `IS NULL`은 하나의 WHERE 절에서 `AND`로 연결할 수 있다.

- 첫 번째 `AND`: BETWEEN의 범위 표시
- 두 번째 `AND`: 서로 다른 조건 연결

NULL 확인에 `email = NULL`을 사용하면 안 된다.

## 3. CASE WHEN — 조건에 따라 값 분류

```sql
SELECT
    name,
    birth_year,
    CASE
        WHEN birth_year <= 1960 THEN '할인'
        WHEN birth_year >= 2000 THEN '청소년'
        ELSE '일반'
    END AS 요금구분
FROM members
ORDER BY birth_year, name
LIMIT 10;
```

### CASE WHEN 기본 구조

```sql
CASE
    WHEN 조건1 THEN 결과1
    WHEN 조건2 THEN 결과2
    ELSE 기본결과
END
```

파이썬의 `if`, `elif`, `else`와 비슷하다.

**오후 실습에서 발생한 오류**

처음에는 다음처럼 작성했다.

```sql
CASE WHEN gender = 'F' THEN '여'
CASE WHEN gender = 'M' THEN '남'
END AS 성별
```

`CASE`를 두 번 작성할 필요는 없다.

수정:

```sql
CASE
    WHEN gender = 'F' THEN '여'
    WHEN gender = 'M' THEN '남'
END AS 성별
```

`CASE`는 한 번 시작하고 `WHEN`을 여러 개 사용할 수 있다.

## 4. ORDER BY와 LIMIT

### 수강료가 높은 강좌 조회

```sql
SELECT course_name, fee
FROM courses
WHERE fee >= 80000
ORDER BY fee DESC, course_name;
```

- `DESC`: 내림차순
- `ASC`: 오름차순(기본값)
- 정렬 기준을 여러 개 작성하면 앞의 기준을 먼저 적용한다.

### 이메일 기준 정렬

```sql
SELECT name, email
FROM members
ORDER BY email DESC, name
LIMIT 10;
```

`LIMIT 10`은 최대 10개의 행을 출력한다.

PostgreSQL에서는 내림차순 정렬 시 별도 지정이 없으면 NULL 값이 앞에 올 수 있다.

## 5. SQL 집계 함수

집계 함수는 여러 행의 데이터를 계산하는 함수다.

| 함수 | 기능 |
|---|---|
| `COUNT(*)` | 전체 행 개수 |
| `COUNT(컬럼)` | NULL이 아닌 값 개수 |
| `COUNT(DISTINCT 컬럼)` | 중복을 제외한 값 개수 |
| `SUM()` | 합계 |
| `AVG()` | 평균 |
| `MIN()` | 최솟값 |
| `MAX()` | 최댓값 |
| `ROUND()` | 반올림 |

### 강좌 통계

```sql
SELECT
    COUNT(*) AS 강좌수,
    MIN(fee) AS 최저수강료,
    MAX(fee) AS 최고수강료,
    SUM(capacity) AS 전체정원,
    ROUND(AVG(fee), 2) AS 평균수강료
FROM courses;
```

### COUNT(*)와 COUNT(컬럼)

```sql
SELECT
    COUNT(*) AS 회원수,
    COUNT(email) AS 이메일있음,
    COUNT(phone) AS 전화번호있음,
    COUNT(DISTINCT region) AS 거주지
FROM members;
```

예를 들어 회원 60명 중 이메일이 없는 회원이 10명이라면:

- `COUNT(*)` = 60
- `COUNT(email)` = 50

**중요:** `COUNT(컬럼)`은 NULL을 세지 않는다.

이는 LEFT JOIN에서 연결되지 않은 데이터의 개수를 0으로 계산할 때 중요하다.

## 6. GROUP BY — 같은 기준으로 묶기

### 월별 매출 계산

```sql
SELECT
    enroll_month AS 신청월,
    COUNT(*) AS 신청건수,
    SUM(pay_amount) AS 매출
FROM enrollments
GROUP BY enroll_month
ORDER BY enroll_month;
```

`GROUP BY enroll_month`는 같은 수강월을 하나의 그룹으로 묶는다.

예시:

| 수강월 | 결제금액 |
|---|---:|
| 2026-09 | 100000 |
| 2026-09 | 150000 |
| 2026-10 | 80000 |

그룹화 결과:

| 수강월 | 신청건수 | 매출 |
|---|---:|---:|
| 2026-09 | 2 | 250000 |
| 2026-10 | 1 | 80000 |

### 여러 컬럼으로 그룹화

```sql
SELECT
    enroll_month,
    status,
    COUNT(*) AS 건수
FROM enrollments
GROUP BY enroll_month, status
ORDER BY enroll_month, status;
```

이 코드는 수강월과 상태의 조합별로 그룹을 만든다.

### GROUP BY에서 가장 중요한 질문

**"최종 결과에서 무엇 하나당 한 행을 출력할 것인가?"**

| 원하는 결과 | 그룹 기준 |
|---|---|
| 월별 신청 건수 | `enroll_month` |
| 강좌별 신청 건수 | `course_id` |
| 종목별·월별 매출 | `sport_name, enroll_month` |
| 강사별 신청 건수 | `instructor_id` |

## 7. HAVING — 그룹별 조건

### WHERE와 HAVING 비교

| 구분 | WHERE | HAVING |
|---|---|---|
| 적용 대상 | 개별 행 | 집계된 그룹 |
| 적용 시점 | GROUP BY 이전 | GROUP BY 이후 |
| 예시 | `status <> '취소'` | `COUNT(*) >= 18` |

### 신청 건수 18건 이상인 강좌

```sql
SELECT
    course_id,
    COUNT(*) AS 누적신청
FROM enrollments
WHERE status <> '취소'
GROUP BY course_id
HAVING COUNT(*) >= 18
ORDER BY 누적신청 DESC, course_id;
```

실행 흐름:

1. 취소되지 않은 신청 기록 조회
2. 강좌 번호별로 그룹화
3. 강좌마다 신청 건수 계산
4. 신청 건수가 18건 이상인 그룹만 선택
5. 신청 건수 내림차순 정렬

### 회원 10명 이상인 지역

```sql
SELECT
    region,
    COUNT(*) AS 회원수
FROM members
GROUP BY region
HAVING COUNT(*) >= 10
ORDER BY COUNT(*) DESC;
```

**주의:** `WHERE COUNT(*) >= 10`처럼 집계 함수 조건을 WHERE에 작성하면 안 된다.

## 8. UNION과 UNION ALL

### UNION ALL

```sql
SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-09'

UNION ALL

SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-10'

UNION ALL

SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-11'

ORDER BY member_id;
```

모든 조회 결과를 중복 포함하여 합친다.

### UNION

```sql
SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-09'

UNION

SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-10'

UNION

SELECT member_id FROM enrollments
WHERE course_id = 4 AND enroll_month = '2026-11'

ORDER BY member_id;
```

중복된 회원 번호를 제거한다.

| 구분 | UNION | UNION ALL |
|---|---|---|
| 중복 제거 | O | X |
| 모든 기록 유지 | X | O |

### 서로 다른 테이블의 결과 합치기

```sql
SELECT '강사' AS 구분, name, phone
FROM instructors
WHERE sport_id = 4

UNION ALL

SELECT '회원' AS 구분, name, phone
FROM members
WHERE region = '영등포구';
```

UNION으로 연결하는 SELECT들은 출력 열 개수가 같고, 대응하는 자료형이 호환되어야 한다.

## 9. JOIN — 여러 테이블 연결

JOIN은 서로 다른 테이블에 저장된 정보를 연결하여 조회하는 기능이다.

### FROM을 먼저 정하는 방법

오늘 실습에서 가장 많이 헷갈렸던 부분이다.

**기준 테이블을 선택할 때는 문제에서 절대 빠지면 안 되는 대상이 무엇인지 먼저 확인한다.**

| 문제 | FROM 기준 |
|---|---|
| 회원 전체 명단 | `members` |
| 수강 신청 기록 | `enrollments` |
| 모든 강사 8명 | `instructors` |
| 상품별 정보 | `product` |

### JOIN ON을 정하는 방법

테이블 사이에서 서로 연결되는 ID를 찾는다.

```sql
FROM enrollments e
JOIN members m
    ON e.member_id = m.member_id
JOIN courses c
    ON e.course_id = c.course_id
```

- `e.member_id = m.member_id`: 신청 기록과 회원 연결
- `e.course_id = c.course_id`: 신청 기록과 강좌 연결

### 오늘 발생했던 JOIN 실수

잘못된 코드:

```sql
JOIN courses c ON c.course_id = c.course_id
```

같은 컬럼을 자기 자신과 비교하고 있다.

수정:

```sql
JOIN courses c ON c.course_id = e.course_id
```

**핵심:** JOIN에서는 테이블 자체의 이름보다 두 테이블을 연결하는 공통 ID가 중요하다.

## 10. INNER JOIN과 LEFT JOIN

### INNER JOIN

두 테이블에서 연결되는 데이터만 출력한다.

```sql
SELECT i.name, c.course_name
FROM instructors i
JOIN courses c
    ON i.instructor_id = c.instructor_id;
```

담당 강좌가 없는 강사는 출력되지 않는다.

### LEFT JOIN

왼쪽 테이블의 모든 행을 유지한다.

```sql
SELECT i.name, c.course_name
FROM instructors i
LEFT JOIN courses c
    ON i.instructor_id = c.instructor_id;
```

강좌가 없는 강사도 출력되며, 강좌 정보에는 NULL이 표시된다.

### 예시

강사:

| instructor_id | name |
|---|---|
| 1 | 김철수 |
| 2 | 이영희 |
| 3 | 박민수 |

강좌:

| course_id | instructor_id |
|---|---|
| 101 | 1 |
| 102 | 1 |
| 103 | 2 |

LEFT JOIN 결과:

| name | course_id |
|---|---|
| 김철수 | 101 |
| 김철수 | 102 |
| 이영희 | 103 |
| 박민수 | NULL |

**중요한 점**

LEFT JOIN은 왼쪽 행을 유지하지만, 오른쪽 테이블에 연결되는 행이 여러 개면 왼쪽 행도 여러 번 출력될 수 있다.

따라서 LEFT JOIN을 사용했다고 해서 강사별로 자동으로 한 행만 출력되는 것은 아니다.

이후 `GROUP BY`로 강사별 집계가 필요하다.

## 11. 서브쿼리(Subquery)

서브쿼리는 SQL 내부에 포함된 또 다른 SELECT 문이다.

### 11-1. WHERE 서브쿼리

평균보다 수강료가 비싼 강좌 조회:

```sql
SELECT course_name, fee
FROM courses
WHERE fee > (
    SELECT AVG(fee)
    FROM courses
)
ORDER BY fee DESC, course_name;
```

안쪽 SELECT에서 평균 수강료를 계산한 뒤 바깥쪽에서 비교한다.

### 11-2. FROM 서브쿼리 — 인라인 뷰

회원별 누적 결제 금액이 40만 원 이상인 회원 조회:

```sql
SELECT
    p.member_id AS 회원번호,
    m.name AS 회원명,
    p.total_paid AS 매출액
FROM (
    SELECT
        member_id,
        SUM(pay_amount) AS total_paid
    FROM enrollments e
    GROUP BY member_id
) AS p
LEFT JOIN members m
    ON p.member_id = m.member_id
WHERE p.total_paid >= 400000
ORDER BY p.total_paid DESC, p.member_id;
```

### 별칭에 대한 질문

기존:

```sql
) AS paid
```

수정:

```sql
) AS p
```

서브쿼리 전체의 결과에 `p`라는 별칭을 붙인 것이다.

- `e`: enrollments 테이블
- `p`: 서브쿼리 결과
- `m`: members 테이블

바깥쪽에서 `p.member_id`, `p.total_paid`처럼 사용할 수 있다.

### 11-3. 스칼라 서브쿼리

하나의 값을 반환하는 서브쿼리다.

```sql
SELECT
    course_name,
    fee,
    ROUND((SELECT AVG(fee) FROM courses), 2)
        AS 전체평균,
    fee - ROUND((SELECT AVG(fee) FROM courses), 2)
        AS 평균과차이
FROM courses;
```

**오류가 발생했던 부분**

```sql
ROUND(SELECT AVG(fee) FROM courses, 2)
```

올바른 문법:

```sql
ROUND((SELECT AVG(fee) FROM courses), 2)
```

안쪽 괄호는 서브쿼리, 바깥쪽 괄호는 ROUND 함수 호출이다.

# 오후 SQL 실습 과제

## 12. 실습 1 — 연락처 점검 대상 회원

### 문제

1970~1989년 출생자 중 이메일이 등록되지 않은 회원을 조회한다.

### 정답 코드

```sql
SELECT
    member_id AS 회원번호,
    name AS 이름,
    birth_year AS 출생연도,
    region AS 거주지역,
    phone AS 전화번호
FROM members
WHERE birth_year BETWEEN 1970 AND 1989
  AND email IS NULL
ORDER BY birth_year ASC, member_id ASC;
```

### 실수했던 부분

처음 작성:

```sql
WHERE birth_year BETWEEN 1970 AND 1989,
```

조건을 연결할 때 쉼표를 사용하면 안 된다.

수정:

```sql
WHERE birth_year BETWEEN 1970 AND 1989
AND email IS NULL
```

또한 `rigion`은 잘못된 컬럼 이름이며 `region`으로 작성해야 한다.

### 배운 점

- BETWEEN은 범위의 양 끝을 포함한다.
- NULL은 `IS NULL`로 확인한다.
- 여러 조건은 `AND`로 연결한다.

## 13. 실습 2 — 지역·성별 회원 현황

### 문제

거주지역과 성별별로 회원을 묶어 회원 수가 5명 이상인 그룹의 회원 수와 평균 출생연도를 조회한다.

### 정답 코드

```sql
SELECT
    region AS 거주지역,
    CASE
        WHEN gender = 'F' THEN '여'
        WHEN gender = 'M' THEN '남'
    END AS 성별,
    COUNT(*) AS 회원수,
    ROUND(AVG(birth_year), 0) AS 평균출생연도
FROM members
GROUP BY region, gender
HAVING COUNT(*) >= 5
ORDER BY 거주지역 ASC, 성별 ASC;
```

### 실수 ① CASE WHEN

처음에는 CASE를 반복하거나 별도로 `gender`를 작성했다.

수정:

```sql
CASE
    WHEN gender = 'F' THEN '여'
    WHEN gender = 'M' THEN '남'
END AS 성별
```

### 실수 ② AVG 함수

처음 작성:

```sql
ROUND(SELECT(AVG(birth_year)) FROM members)
```

수정:

```sql
ROUND(AVG(birth_year), 0)
```

이미 FROM에서 members를 조회하므로 별도 서브쿼리가 필요하지 않다.

### 실수 ③ GROUP BY 누락

집계 함수와 일반 컬럼을 함께 사용하면서 GROUP BY를 작성하지 않아 오류가 발생했다.

```sql
GROUP BY region, gender
```

### 실수 ④ 정렬

```sql
ORDER BY region, gender
```

원본 성별 값은 F, M이므로 F가 먼저 나온다.

문제에서는 남 → 여 순서이므로:

```sql
ORDER BY 거주지역, 성별
```

CASE WHEN으로 변환된 별칭을 사용했다.

### 배운 점

- CASE WHEN으로 출력 값을 변경할 수 있다.
- GROUP BY에서 여러 컬럼을 기준으로 묶을 수 있다.
- 회원 수 5명 이상이라는 집계 조건은 HAVING을 사용한다.
- ORDER BY에서 SELECT 별칭을 사용할 수 있다.

## 14. 실습 3 — 10월 수강 취소 명단

### 문제

2026년 10월에 수강을 취소한 회원의 이름, 전화번호, 강좌명과 수강월을 조회한다.

### 정답 코드

```sql
SELECT
    m.name AS 회원명,
    m.phone AS 전화번호,
    c.course_name AS 강좌명,
    e.enroll_month AS 수강월
FROM enrollments e
JOIN members m
    ON m.member_id = e.member_id
JOIN courses c
    ON c.course_id = e.course_id
WHERE e.enroll_month = '2026-10'
  AND e.status = '취소'
ORDER BY m.name;
```

### 실수 ① 잘못된 컬럼 선택

처음 작성:

```sql
start_time AS 수강월
```

`start_time`은 강좌 시작 시간이다.

수강월은 `enroll_month`를 사용해야 한다.

### 실수 ② JOIN 뒤에 컬럼 사용

처음 작성:

```sql
JOIN m.member_id ON ...
```

JOIN 뒤에는 테이블 이름을 작성해야 한다.

```sql
JOIN members m ON ...
```

### 실수 ③ 같은 컬럼끼리 JOIN

처음 작성:

```sql
JOIN courses c ON c.course_id = c.course_id
```

수정:

```sql
JOIN courses c ON c.course_id = e.course_id
```

### 배운 점

- 여러 테이블을 연결할 때 공통 ID를 찾는다.
- JOIN 뒤에는 테이블 이름, ON 뒤에는 연결 조건을 작성한다.
- 테이블별 별칭을 구분해서 사용한다.

## 15. 실습 4 — 종목별 월 매출

### 문제

종목과 수강월별 실제 수강 인원 및 매출을 구하고, 취소 기록을 제외한 매출이 100만 원 이상인 결과만 조회한다.

### 정답 코드

```sql
SELECT
    s.sport_name AS 종목,
    e.enroll_month AS 수강월,
    COUNT(*) AS 수강인원,
    SUM(e.pay_amount) AS 매출
FROM enrollments e
JOIN courses c
    ON e.course_id = c.course_id
JOIN sports s
    ON c.sport_id = s.sport_id
WHERE e.status <> '취소'
GROUP BY s.sport_name, e.enroll_month
HAVING SUM(e.pay_amount) >= 1000000
ORDER BY 종목, 수강월;
```

### 실수 ① COUNT와 SUM 구분

처음에는 `c.capacity`를 수강 인원으로 사용하려고 했다.

그러나:

- `capacity`: 강좌 최대 정원
- `COUNT(*)`: 취소를 제외한 신청 건수
- `fee`: 강좌 기본 수강료
- `SUM(pay_amount)`: 실제 결제액 합계

신청 1건이 수강 인원 1명을 의미한다는 과제 전제에서 COUNT(*)를 사용했다.

### 실수 ② 테이블 이름

처음 작성:

```sql
FROM enrollmentse e
```

수정:

```sql
FROM enrollments e
```

### 실수 ③ 취소 상태 제외

처음 작성:

```sql
WHERE status IS NOT '취소'
```

수정:

```sql
WHERE e.status <> '취소'
```

### 실수 ④ 매출 100만 원 이상

처음에는 다음처럼 작성했다.

```sql
WHERE 매출 >= 1000000
```

매출은 SUM으로 집계한 값이므로 HAVING에서 검사한다.

```sql
HAVING SUM(e.pay_amount) >= 1000000
```

### 실수 ⑤ 별칭 사용

PostgreSQL에서는 다음 코드가 가능하다.

```sql
GROUP BY 종목, 수강월
```

하지만 HAVING에서는 SELECT 별칭인 매출을 직접 사용할 수 없으므로 집계 함수를 작성해야 한다.

```sql
HAVING SUM(e.pay_amount) >= 1000000
```

### 실수 ⑥ 한글 정렬

조회 결과에서 `수영`이 `골프연습`보다 먼저 나오는 문제가 발생했다.

한국어 정렬 규칙을 지정하는 방법을 추가로 확인했다.

```sql
ORDER BY
    s.sport_name COLLATE "ko-x-icu",
    e.enroll_month;
```

`COLLATE`는 문자열의 정렬 규칙을 지정하는 기능이다.

현재 DB에 해당 정렬 규칙이 존재해야 사용할 수 있다.

**별칭과 COLLATE**

```sql
ORDER BY 종목 COLLATE "ko-x-icu"
```

처럼 SELECT 별칭에 표현식을 적용하면 PostgreSQL에서 별칭을 인식하지 못할 수 있으므로 원본 컬럼을 사용한다.

### 매출 소수점 제거

수업에서 배운 방법:

```sql
ROUND(SUM(e.pay_amount), 0) AS 매출
```

하지만 ROUND는 숫자를 반올림하는 함수이며, 결과의 소수 자릿수 표시까지 항상 없애는 것은 아니다.

추가로 알게 된 문법:

```sql
SUM(e.pay_amount)::BIGINT AS 매출
```

`::BIGINT`는 정수형으로 자료형을 변환하는 PostgreSQL 문법이다.

**수업에서 배운 문법은 ROUND이며, `::BIGINT`와 `COLLATE`는 실습 문제 해결 과정에서 추가로 알아본 내용이다.**

## 16. 실습 5 — 강사별 담당 강좌 수와 11월 신청 건수

### 문제

강사 8명 모두를 대상으로 담당 강좌 수와 2026년 11월 수강 신청 건수를 조회한다.

강좌가 없는 강사도 출력하며 두 값은 0이어야 한다.

### 최종 코드

```sql
SELECT
    i.name AS 강사명,
    s.sport_name AS 종목,
    COUNT(DISTINCT c.course_id) AS 담당강좌수,
    COUNT(e.course_id) AS 이번달신청
FROM instructors i
LEFT JOIN courses c
    ON i.instructor_id = c.instructor_id
LEFT JOIN sports s
    ON i.sport_id = s.sport_id
LEFT JOIN enrollments e
    ON c.course_id = e.course_id
   AND e.enroll_month = '2026-11'
GROUP BY i.instructor_id, i.name, s.sport_name
ORDER BY 이번달신청 DESC, 강사명;
```

### 16-1. FROM 선택

문제의 핵심 조건은 강사 8명이 모두 출력되어야 한다는 것이다.

따라서 강사를 기준으로 시작한다.

```sql
FROM instructors i
```

### 16-2. 테이블 연결 관계

강사에서 필요한 다른 테이블을 연결한다.

```text
instructors
    |
    | instructor_id
    v
  courses
    |
    | course_id
    v
 enrollments
```

담당 종목은 강사와 sports를 sport_id로 연결한다.

```sql
LEFT JOIN sports s
    ON i.sport_id = s.sport_id
```

### 16-3. LEFT JOIN이 필요한 이유

담당 강좌가 없는 강사도 출력해야 하므로 LEFT JOIN을 사용했다.

```sql
LEFT JOIN courses c
    ON i.instructor_id = c.instructor_id
```

만약 INNER JOIN을 사용한다면 강좌가 없는 강사는 결과에서 제외된다.

### 16-4. 11월 조건을 ON에 작성

```sql
LEFT JOIN enrollments e
    ON c.course_id = e.course_id
   AND e.enroll_month = '2026-11'
```

WHERE에 11월 조건을 작성하면 11월 신청이 없는 강사가 결과에서 빠질 수 있다.

ON에서 11월 기록만 연결하면 신청이 없는 강사도 남는다.

### 16-5. COUNT(*) 대신 COUNT(컬럼)

```sql
COUNT(e.course_id) AS 이번달신청
```

LEFT JOIN에서 연결되는 신청이 없으면 e.course_id는 NULL이므로 COUNT 결과가 0이다.

반대로 COUNT(*)는 강좌가 없는 강사도 LEFT JOIN에 의해 한 행으로 남기 때문에 1이 나올 수 있다.

### 16-6. COUNT(DISTINCT)가 필요한 이유

```sql
COUNT(DISTINCT c.course_id) AS 담당강좌수
```

강사 한 명이 강좌 2개를 담당한다고 가정하자.

- 강좌 A: 신청 5건
- 강좌 B: 신청 3건

JOIN 이후에는 총 8행이 만들어질 수 있다.

따라서:

- `COUNT(c.course_id)` → 8
- `COUNT(DISTINCT c.course_id)` → 2
- `COUNT(e.course_id)` → 8

담당 강좌 수를 정확하게 계산하기 위해 중복된 강좌 번호를 제거한다.

### 16-7. GROUP BY 실수

처음 작성:

```sql
GROUP BY 강사명, 종목, c.course_id
```

이렇게 하면 강사별이 아니라 강사·강좌별로 묶인다.

실제 실행 결과는 강사 8명 대신 13행이었다.

수정:

```sql
GROUP BY i.instructor_id, i.name, s.sport_name
```

강사 ID를 기준으로 묶기 때문에 강사별 한 행을 만들 수 있다.

### 16-8. 이름만으로 GROUP BY해도 될까?

```sql
GROUP BY i.name, s.sport_name
```

현재 강사들의 이름과 종목 조합이 모두 다르다면 같은 결과가 나올 수 있다.

하지만 동명이인이고 담당 종목도 같은 강사가 존재하면 두 강사가 하나의 그룹으로 합쳐질 수 있다.

따라서 고유한 강사 번호를 포함하는 것이 안전하다.

### 16-9. 최종 정렬

```sql
ORDER BY 이번달신청 DESC, 강사명 ASC;
```

- 이번달신청: 많은 순서
- 강사명: 신청 건수가 같으면 이름순

### 마지막으로 확인한 예상 집계 결과

| 강사명 | 종목 | 담당강좌수 | 이번달신청 |
|---|---|---:|---:|
| 배수민 | 스포츠댄스 | 3 | 16 |
| 오민재 | 수영 | 2 | 10 |
| 임도현 | 골프연습 | 1 | 6 |
| 한지수 | 수영 | 3 | 5 |
| 강태호 | 헬스 | 1 | 4 |
| 서하늘 | 골프연습 | 1 | 4 |
| 윤서연 | 헬스 | 1 | 4 |
| 차예린 | 스포츠댄스 | 0 | 0 |

위 결과는 사용자가 공유한 13행을 강사별로 재집계한 예상값이다.

## 17. LEFT JOIN과 GROUP BY 핵심 비교

| 구분 | LEFT JOIN | GROUP BY |
|---|---|---|
| 목적 | 테이블 연결 | 데이터 그룹화 |
| 기준 | 연결 조건 ON | 그룹 기준 컬럼 |
| 결과 | 연결 행이 많으면 행 증가 | 같은 그룹을 하나로 집계 |
| 활용 | 회원·강좌·강사 정보 연결 | 강사별·월별 통계 |

### LEFT JOIN의 핵심

**왼쪽 테이블을 기준으로 데이터를 연결하되, 연결 대상이 없어도 왼쪽 행을 유지한다.**

### GROUP BY의 핵심

**최종 결과에서 무엇 하나당 한 행을 출력할지 생각해서 그룹 기준을 정한다.**

예를 들어 강사마다 한 행이면 강사 ID, 월마다 한 행이면 수강월, 종목과 월마다 한 행이면 종목과 수강월을 기준으로 묶는다.

## 18. SQL 문제 해결 순서

오늘 오후 실습을 통해 정리한 문제 풀이 순서다.

### STEP 1. 출력 대상 찾기

문제에서 누구 또는 무엇을 출력해야 하는지 확인한다.

예: 강사 8명 모두 → instructors

### STEP 2. 필요한 테이블 확인

출력할 컬럼이 어느 테이블에 저장되어 있는지 찾는다.

예:

- 강사명 → instructors
- 종목명 → sports
- 담당 강좌 → courses
- 신청 기록 → enrollments

### STEP 3. JOIN 연결 기준 확인

서로 연결되는 ID를 찾는다.

예:

```sql
i.instructor_id = c.instructor_id
```

### STEP 4. INNER JOIN 또는 LEFT JOIN 선택

- 연결된 데이터만 필요 → INNER JOIN
- 기준 테이블의 모든 행이 필요 → LEFT JOIN

### STEP 5. WHERE 조건

집계하기 전에 제외할 행을 결정한다.

단, LEFT JOIN에서 연결 대상이 없는 행까지 유지해야 한다면 조건을 ON에 넣어야 하는 경우가 있다.

### STEP 6. GROUP BY

어떤 단위로 결과를 묶을지 결정한다.

### STEP 7. HAVING

집계 결과에 조건이 있다면 적용한다.

### STEP 8. ORDER BY

문제에서 요구한 정렬 기준으로 출력한다.
